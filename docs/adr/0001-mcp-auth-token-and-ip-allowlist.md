# MCP の口の認証は、DB のエージェント用トークンと IP 許可リストにする (OAuth にしない)

MCP の口を最初に使うのは、持ち主の PC の Claude Code と devloop のランナーだけである。そのため認証は、画面で発行する DB のエージェント用トークン (ハッシュだけを保存し、権限・期限・失効を持つ) と、DB で管理する IP 許可リストの組み合わせにした。トークンが漏れても、許可した IP の外からは使えない。

OAuth にすれば claude.ai のコネクタやスマホからも使えるが、見送った。今の Better Auth (1.7.7) の本体には OAuth の認可サーバーになるプラグインが無く、手間に見合わないためである。

## Consequences

- claude.ai のコネクタ、claude.ai/code のクラウドセッション、ルーティンからは呼べない (送信元が Anthropic のサーバーなので IP で弾かれる)。そこから使いたくなったら、この決定を見直して OAuth を足す。
- 家の回線の IP が変わると弾かれる。画面の「今の IP を許可」で戻す。
- アプリがローカルで動くとき (ローカル機能が有効) は、トークンと IP の確認をしない。代わりに `127.0.0.1` だけで待ち受け、Host と Origin を確認する。PC のファイアウォールでは、ブラウザから localhost に送られる通信 (DNS リバインディングなど) を防げないためである。
