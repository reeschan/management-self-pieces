# Node の中身の正をアプリの DB に移し、node.yaml をやめる

これまで Node の中身は、各リポジトリのルートに置く `node.yaml` を正とし、アプリの DB は「消えても GitHub と Asana から作り直せる」写しとしてきた。これをやめ、Node の項目 (kind・title・summary・status・tags・links・関係・meta・詳細と図のパス) はアプリの DB を正とし、持ち主が画面で登録・編集する。`node.yaml` の取り込みと `/schema/node.json` は廃止する。

理由は、成果物ごとにリポジトリへ `node.yaml` を書いて保つ手間が大きく、実際に書かれたのは 1 件だけだったため。また、リポジトリを持たない成果物 (スキル・文書など) も Node にしたかったため。

## Considered Options

- `node.yaml` を任意の取り込み元として残す: 正が 2 つになり、どちらが勝つかの決まりと、その不具合が増えるのでやめた。
- DB の定期バックアップを GitHub にコミットする: 書き込み権限と Cron の失敗の扱いが増えるわりに、今の規模では手動の書き出しで足りるので見送った。

## Consequences

- 「DB は作り直せる」という原則は、Node については成り立たなくなる。備えは、設定画面からの JSON の書き出しと読み込み (手動) だけ。Asana との対応は、これまでどおりプロジェクトの notes から作り直せる。
- Node を参照するテーブルは、Node を消すとすべて一緒に消える (cascade)。そのため、リポジトリが消えたり、GitHub App から外されたりしても、Node は自動では消さない。画面に「届かない」と出すだけにする。
- 詳細の Markdown と図は、これまでどおり Node のリポジトリから読む。リポジトリの無い Node には詳細が無い。
- [ADR 0002](0002-board-source-of-truth-in-asana.md) は「作り直せる」原則を理由に看板の正を Asana に置いた。その原則は弱まるが、看板は持ち主が Asana で直接動かす前提があるので、正は Asana のままにする。
