# PBI-001: Next.js の土台と依存パッケージ・スクリプトをそろえる

- 担当モデル: sonnet (select_model.py: Jev 不可のため score=1)
- 依存: なし

## 目的
成果物 (Node) を 3D で眺め Asana でチケット管理する個人用アプリ `management-self-pieces` の土台を作る。後続の PBI が `package.json` を取り合わないよう、MVP で使う依存パッケージと npm スクリプトはこの PBI でまとめて入れる。設計の全体像は `docs/DESIGN.md`。

## 対象
リポジトリのルート: `C:\Users\owner\dev\management-self-pieces` (git 初期化済み、`docs/` だけがある)

1. create-next-app で Next.js (App Router, TypeScript, Tailwind CSS, ESLint, `src/` ディレクトリ, import alias `@/*`, pnpm) を作る。ルートには既に `docs/` と `.git` があるので、**`../msp-scaffold` に作ってから中身をルートへ移す** (`.git` と `node_modules` は移さない。移したあと `../msp-scaffold` は削除し、ルートで `pnpm install`)
   - 例: `pnpm create next-app@latest ../msp-scaffold --ts --app --src-dir --tailwind --eslint --import-alias "@/*" --use-pnpm --no-git --yes` (フラグ名が違えば `--help` で確認して合わせる)
2. 依存パッケージを追加する
   - dependencies: `better-auth` `drizzle-orm` `@neondatabase/serverless` `zod` (v4) `yaml` `octokit` `@octokit/webhooks-methods` `react-force-graph-3d` `three` `react-markdown` `remark-gfm` `mermaid`
   - devDependencies: `drizzle-kit` `vitest` `vite-tsconfig-paths` `tsx` `dotenv` `@types/three`
3. `package.json` の scripts を次にする (既存の dev/build/start/lint は残す)
   - `"typecheck": "tsc --noEmit"`
   - `"test:unit": "vitest run"`
   - `"db:generate": "drizzle-kit generate"`
   - `"db:migrate": "drizzle-kit migrate"`
   - `"db:seed": "tsx --env-file-if-exists=.env.local scripts/seed.mts"`
4. `vitest.config.mts` を作る (`vite-tsconfig-paths` プラグインで `@/*` を解決、`environment: "node"`、`include: ["src/**/*.test.ts", "scripts/**/*.test.ts"]`)
5. `src/lib/smoke.test.ts` に `expect(1 + 1).toBe(2)` だけのテストを 1 つ置く (Vitest が動くことの確認用)
6. `.env.example` を作る。値は空で、各行の上に 1 行の日本語コメントで用途を書く。キー: `APP_URL` `DATABASE_URL` `BETTER_AUTH_SECRET` `ALLOWED_EMAILS` (カンマ区切り) `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` `GITHUB_APP_ID` `GITHUB_APP_PRIVATE_KEY` `GITHUB_APP_CLIENT_ID` `GITHUB_APP_CLIENT_SECRET` `GITHUB_WEBHOOK_SECRET` `ASANA_PAT` `ASANA_WORKSPACE_GID` `ASANA_TEAM_GID` (任意。組織のワークスペースでは必要) `CRON_SECRET`
7. `.gitignore` で `.env*` を無視しつつ `.env.example` は追跡されるようにする (`!.env.example`)

## 触らない範囲
- `docs/` 配下 (DESIGN.md, TODO.md, pbi/)
- `.git`
- create-next-app が作るページの見た目 (`src/app/page.tsx` などは生成されたままでよい)

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0
2. 検証コマンド 2 が終了コード 0 で、1 件以上のテストが pass
3. 検証コマンド 3 が終了コード 0
4. 検証コマンド 4 の出力に `ok` が 2 行出る (依存とスクリプトがそろっている)
5. 検証コマンド 5 の出力が `ok` (`.env.example` が追跡対象になる)

## 検証コマンド
1. `pnpm typecheck`
2. `pnpm test:unit`
3. `pnpm build`
4. `node -e "const p=require('./package.json');const d={...p.dependencies,...p.devDependencies};const need=['better-auth','drizzle-orm','@neondatabase/serverless','zod','yaml','octokit','@octokit/webhooks-methods','react-force-graph-3d','three','react-markdown','remark-gfm','mermaid','drizzle-kit','vitest','vite-tsconfig-paths','tsx','dotenv','@types/three'];const miss=need.filter(n=>!d[n]);console.log(miss.length?'missing '+miss:'ok');const s=['typecheck','test:unit','db:generate','db:migrate','db:seed'].filter(k=>!p.scripts[k]);console.log(s.length?'missing '+s:'ok');console.log(d.zod)"`
5. `git check-ignore -q .env.example && echo ignored || echo ok`

## 補足
- Windows (Git Bash) で作業する。pnpm 12、Node 26
- `pnpm create` が対話で止まる場合は `--yes` を付けるか、足りないフラグを追加する
- zod は v4 系 (`^4`) になっていること (検証コマンド 4 の 3 行目で確認)
- pnpm がビルドスクリプトの承認を求める (`pnpm approve-builds`) 場合は、`esbuild` など必要なものを `package.json` の `pnpm.onlyBuiltDependencies` に入れて非対話で通す
