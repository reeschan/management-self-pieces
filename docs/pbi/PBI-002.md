# PBI-002: 環境変数を機能ごとに検証する env モジュール

- 担当モデル: opus (select_model.py: sensitive)
- 依存: PBI-001

## 目的
環境変数を Zod で検証し、設定漏れをすぐ分かるようにする。`next build` は環境変数が無くても通る必要があるので、**読み込み時には検証せず、機能ごとの関数を呼んだときに検証する** (遅延評価)。DB・認証・GitHub・Asana・Cron の各モジュールはこのファイルの関数だけを通して環境変数を読む。

## 対象
- 新規 `src/lib/env.ts`
- 新規 `src/lib/env.test.ts`

`src/lib/env.ts` が export するもの (すべて引数 `source: Record<string, string | undefined> = process.env` を取り、結果を返す。キャッシュはしない):

| 関数 | 検証するキー | 返す値 |
|---|---|---|
| `dbEnv(source?)` | `DATABASE_URL` (URL) | `{ databaseUrl }` |
| `authEnv(source?)` | `APP_URL` (URL) `BETTER_AUTH_SECRET` (16 文字以上) `ALLOWED_EMAILS` `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` `GITHUB_APP_CLIENT_ID` `GITHUB_APP_CLIENT_SECRET` | `{ appUrl, secret, allowedEmails: string[], google: { clientId, clientSecret }, github: { clientId, clientSecret } }` |
| `githubEnv(source?)` | `GITHUB_APP_ID` `GITHUB_APP_PRIVATE_KEY` `GITHUB_WEBHOOK_SECRET` | `{ appId, privateKey, webhookSecret }` |
| `asanaEnv(source?)` | `APP_URL` (URL) `ASANA_PAT` `ASANA_WORKSPACE_GID`、任意で `ASANA_TEAM_GID` | `{ appUrl, pat, workspaceGid, teamGid?: string }` (`ASANA_TEAM_GID` が未設定か空なら `teamGid` は undefined) |
| `cronEnv(source?)` | `CRON_SECRET` (16 文字以上) | `{ cronSecret }` |

- 文字列はすべて空文字を不可とする (`z.string().min(1)`)
- `ALLOWED_EMAILS` はカンマ区切りを分割し、前後の空白を除き、小文字にし、空要素を捨てる。結果が 0 件なら検証エラー
- `GITHUB_APP_PRIVATE_KEY` は文字列中の `\n` (バックスラッシュと n の 2 文字) を改行に置き換える (Vercel の環境変数で 1 行に入れられるように)
- `APP_URL` は末尾の `/` を取り除く
- 検証に失敗したら `EnvError` (export する。`Error` を継承) を投げる。メッセージに**足りない・不正なキー名をすべて**含め、**値は含めない**

## 触らない範囲
- `package.json` と lockfile (依存は PBI-001 で導入済み)
- `src/app/` 配下
- `docs/` 配下

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、`src/lib/env.test.ts` のテストがすべて pass する。テストは少なくとも次を含む
   - 各関数が正しい入力で期待どおりの値を返す
   - `ALLOWED_EMAILS=" A@x.com, ,b@Y.com "` が `["a@x.com", "b@y.com"]` になる
   - `GITHUB_APP_PRIVATE_KEY` の `\n` が改行になる
   - キーが欠けているとき `EnvError` が投げられ、メッセージに欠けたキー名が含まれ、渡した他の値 (例: 秘密の文字列) が含まれない
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 の出力が空 (env.ts 以外で `process.env.` を直接読んでいない。ただしテストと設定ファイルは除く)

## 検証コマンド
1. `pnpm test:unit src/lib/env.test.ts`
2. `pnpm typecheck`
3. `grep -rn "process\.env\." src --include=*.ts --include=*.tsx | grep -v "src/lib/env.ts" | grep -v "\.test\.ts"`

## 補足
- Zod v4 を使う (`import { z } from "zod"`)。URL は `z.url()`
- 機能ごとに `z.object({...})` を定義し、`safeParse` の `error.issues` の `path` からキー名を集めてメッセージを作るとよい
