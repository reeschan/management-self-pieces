# PBI-003: node.yaml の Zod スキーマ・kind 登録・解析・JSON Schema 公開

- 担当モデル: sonnet (select_model.py: Jev 不可のため score=1)
- 依存: PBI-001

## 目的
各リポジトリのルートに置く `node.yaml` が Node の内容の正になる。その仕様を Zod スキーマで 1 か所に定め、アプリでの検証・エディタ補完用の JSON Schema・将来の MCP の入力スキーマに使い回す。kind (種類) ごとの `meta` は登録制にし、kind を足すだけで拡張できるようにする。

## 対象
- 新規 `src/lib/manifest/kinds.ts`: kind の登録
- 新規 `src/lib/manifest/schema.ts`: `NodeManifest` などのスキーマと型
- 新規 `src/lib/manifest/parse.ts`: YAML 文字列の解析と検証
- 新規 `src/lib/manifest/json-schema.ts`: JSON Schema の生成
- 新規 `src/app/schema/node.json/route.ts`: `GET /schema/node.json` で JSON Schema を返す
- 新規 `src/lib/manifest/manifest.test.ts`

### kinds.ts
```ts
export const kinds = {
  app:     { label: "アプリ",     meta: z.object({ url: z.url().optional(), deployTarget: z.string().optional() }) },
  skill:   { label: "スキル",     meta: z.object({ trigger: z.string().optional(), runtime: z.string().optional() }) },
  library: { label: "ライブラリ", meta: z.object({ packageName: z.string().optional() }) },
  doc:     { label: "文書",       meta: z.object({}) },
  infra:   { label: "インフラ",   meta: z.object({}) },
  other:   { label: "その他",     meta: z.object({}) },
} as const satisfies Record<string, { label: string; meta: z.ZodObject }>;
export type KindId = keyof typeof kinds;
export const kindIds: [KindId, ...KindId[]]  // Object.keys(kinds) から作る
```
各 `meta` の object は未知のキーを許す (`.loose()` もしくは `.passthrough()` 相当、Zod v4 の API に合わせる)。

### schema.ts
`NodeManifest` (z.object) の項目:

| 項目 | 型 | 既定値 |
|---|---|---|
| `id` | `/^[a-z0-9][a-z0-9-]{0,62}$/` | 必須 |
| `kind` | `z.enum(kindIds)` | 必須 |
| `title` | 1〜100 文字 | 必須 |
| `summary` | 1〜200 文字 | 必須 |
| `detail` | リポジトリ内の相対パス文字列 | `"README.md"` |
| `diagrams` | `{ path: 相対パス, title?: string }` の配列 | `[]` |
| `links` | `z.record(z.string(), z.url())` | `{}` |
| `status` | `"idea" \| "active" \| "maintenance" \| "archived"` | `"active"` |
| `tags` | 文字列の配列 | `[]` |
| `relations` | `{ type: RelationType, to: id と同じ形式 }` の配列 | `[]` |
| `meta` | `z.record(z.string(), z.unknown())` | `{}` |

- `RelationType` = `"uses" | "depends-on" | "derived-from" | "part-of" | "related"` (z.enum として export)
- 相対パスは「空でない」「`/` で始まらない」「`..` のセグメントを含まない」「`\` を含まない」こと。`RepoPath` として export する
- `export type NodeManifest = z.output<typeof NodeManifest>` も export する
- 各項目に `.describe("日本語の説明")` を付ける (JSON Schema の description になり、エディタに表示される)

### parse.ts
```ts
export type ParseResult =
  | { ok: true; manifest: NodeManifest }
  | { ok: false; errors: string[] };
export function parseManifest(yamlText: string): ParseResult;
```
- `yaml` パッケージで解析。YAML の構文エラーは `ok: false` (例外を外に出さない)
- `NodeManifest` で検証したあと、`kinds[kind].meta` で `meta` を検証する
- `errors` の各要素は `"<パス>: <メッセージ>"` の形 (例 `"meta.url: Invalid URL"`)。ルートの問題はパスを `"(root)"` とする

### json-schema.ts / route.ts
- `nodeJsonSchema()` は `z.toJSONSchema(NodeManifest, { io: "input" })` に `$id`・`title: "node.yaml"` を足したオブジェクトを返す
- route は `Response.json(nodeJsonSchema())` を返す。`export const dynamic = "force-static"`

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、テストがすべて pass する。テストは少なくとも次を含む
   - 最小の YAML (id/kind/title/summary のみ) が `ok: true` になり、既定値 (detail="README.md", status="active", 配列は空) が入る
   - すべての項目を書いた YAML が `ok: true` になる
   - id が不正 (大文字を含む)、kind が未登録、`diagrams[0].path` が `../x.svg` のとき `ok: false` で、errors に該当パスが含まれる
   - kind=app で `meta.url` が URL でないと `ok: false` で、errors に `meta.url` が含まれる
   - YAML の構文エラーで `ok: false` になり、例外を投げない
   - `nodeJsonSchema()` の `properties` に `id` `kind` `relations` があり、`kind` の enum に `"skill"` が含まれる
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0 で、出力に `/schema/node.json` が含まれる
