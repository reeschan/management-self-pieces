# PBI-004: Drizzle のテーブル定義と DB クライアント

- 担当モデル: opus (select_model.py: sensitive)
- 依存: PBI-002

## 目的
Neon (Postgres) を Drizzle で使う。アプリの DB は GitHub と Asana から作り直せる「表示用の一時保存」で、Node・関係・外部連携の対応・タスクの一時保存・同期の状態・取り込みエラーを持つ。Better Auth のテーブルは PBI-005 で `src/db/auth-schema.ts` に足す。

## 対象
- 新規 `src/db/schema.ts`
- 新規 `src/db/client.ts`
- 新規 `drizzle.config.ts`
- 生成物 `drizzle/` (マイグレーション SQL。`pnpm db:generate` で作る)

### schema.ts (`drizzle-orm/pg-core`)
| テーブル (TS 名 / DB 名) | 列 |
|---|---|
| `nodes` / `nodes` | `id` text PK, `kind` text not null, `title` text not null, `summary` text not null, `status` text not null, `detailPath` text not null, `tags` jsonb `$type<string[]>()` not null default `[]`, `links` jsonb `$type<Record<string,string>>()` not null default `{}`, `diagrams` jsonb `$type<{path:string;title?:string}[]>()` not null default `[]`, `meta` jsonb `$type<Record<string,unknown>>()` not null default `{}`, `sourceRepo` text not null, `sourceSha` text not null, `updatedAt` timestamptz not null default now |
| `relations` / `relations` | `fromId` text not null (FK → nodes.id, on delete cascade), `toId` text not null (FK なし。相手がまだ無くてもよい), `type` text not null。PK は (fromId, toId, type) |
| `externalRefs` / `external_refs` | `nodeId` text not null (FK → nodes.id cascade), `provider` text not null, `externalId` text not null, `url` text, `createdAt` timestamptz default now。PK は (nodeId, provider)。(provider, externalId) に unique index |
| `taskCache` / `task_cache` | `provider` text, `externalId` text, `projectExternalId` text not null, `nodeId` text not null, `name` text not null, `completed` boolean not null, `dueOn` text, `url` text, `updatedAt` timestamptz default now。PK は (provider, externalId)。(provider, projectExternalId) に index |
| `syncState` / `sync_state` | `key` text PK, `value` text not null, `updatedAt` timestamptz default now |
| `importErrors` / `import_errors` | `id` serial PK, `sourceRepo` text not null, `path` text not null, `message` text not null, `createdAt` timestamptz default now。sourceRepo に index |

列名は DB 側で snake_case (例 `source_repo`) にする。`export type NodeRow = typeof nodes.$inferSelect` など、各テーブルの Select / Insert 型を export する。

### client.ts
- `getDb()` を export する。初回呼び出し時に `dbEnv()` (`@/lib/env`) で `DATABASE_URL` を読み、`drizzle-orm/neon-http` と `@neondatabase/serverless` の `neon()` でクライアントを作ってキャッシュする。モジュールの読み込み時には何もしない (環境変数なしで build が通るように)
- `schema` を渡して `db.query` が使えるようにする。PBI-005 で `auth-schema.ts` を足すので、`import * as appSchema from "./schema"` を `{ ...appSchema }` として渡す形にしておく
- `export type Db = ReturnType<typeof getDb>`

### drizzle.config.ts
- `dotenv` で `.env.local` を読み込む (`config({ path: ".env.local" })`)
- `schema: ["./src/db/schema.ts", "./src/db/auth-schema.ts"]` と書きたいが auth-schema はまだ無いので、`schema: "./src/db/*schema.ts"` (glob) にする
- `out: "./drizzle"`, `dialect: "postgresql"`, `dbCredentials.url` は `process.env.DATABASE_URL ?? ""`

## 触らない範囲
- `package.json` と lockfile (スクリプトは PBI-001 で追加済み)
- `src/lib/env.ts`
- `src/lib/manifest/`、`docs/`

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、`drizzle/` に `CREATE TABLE "nodes"` を含む SQL ファイルができる
2. 検証コマンド 2 の出力が `6` (テーブルが 6 つ)
3. 検証コマンド 3 が終了コード 0
4. 検証コマンド 4 が終了コード 0 (環境変数なしで build が通る)

## 検証コマンド
1. `pnpm db:generate && grep -l 'CREATE TABLE "nodes"' drizzle/*.sql`
2. `cat drizzle/*.sql | grep -c 'CREATE TABLE'`
3. `pnpm typecheck`
4. `pnpm build`

## 補足
- `drizzle-kit generate` は DB に接続しないので、`DATABASE_URL` が無くても動く
- neon-http ドライバはトランザクション (`db.transaction`) に対応していない。複数の書き込みをまとめたいときは `db.batch([...])` を使う (後続 PBI 向けの注意。この PBI では不要)
- `process.env` を読んでよいのは `drizzle.config.ts` だけ (アプリのコードは `@/lib/env` を使う)
