# PBI-005: Better Auth の設定 (Google / GitHub、許可リスト、アカウント連携)

- 担当モデル: opus (select_model.py: sensitive)
- 依存: PBI-004

## 目的
アプリは公開 URL (Vercel) で動くが、使うのは持ち主 1 人だけ。Better Auth で Google と GitHub のログインを用意し、**許可リスト (`ALLOWED_EMAILS`) にないメールアドレスのユーザーは作らせない**ことで、持ち主以外が入れないようにする。どちらでログインしても同じユーザーになるよう、アカウント連携を有効にする。GitHub のログインには GitHub App の Client ID / Secret を使う。

## 対象
- 新規 `src/lib/auth/allowlist.ts`: `isAllowedEmail(email: string | null | undefined, allowed: readonly string[]): boolean` (前後の空白を除き小文字にして完全一致。空や null は false)
- 新規 `src/lib/auth/allowlist.test.ts`
- 新規 `src/db/auth-schema.ts`: Better Auth の Drizzle スキーマ (user / session / account / verification)
- 変更 `src/db/client.ts`: `auth-schema` も schema に含める
- 新規 `src/lib/auth/server.ts`: `getAuth()` (初回呼び出しで `betterAuth(...)` を作ってキャッシュ) と `getSession()` (`getAuth().api.getSession({ headers: await headers() })` の薄いラッパー)
- 新規 `src/lib/auth/client.ts`: `createAuthClient()` (`better-auth/react`) の `authClient` を export
- 新規 `src/app/api/auth/[...all]/route.ts`: `GET` と `POST` を export。各リクエストで `toNextJsHandler(getAuth())` を呼んで処理する (モジュールの読み込み時に `getAuth()` を呼ばない)
- 生成物 `drizzle/` の追加マイグレーション (`pnpm db:generate`)

### betterAuth の設定
```ts
betterAuth({
  baseURL: authEnv().appUrl,
  secret: authEnv().secret,
  database: drizzleAdapter(getDb(), { provider: "pg", schema: authSchema }),
  socialProviders: {
    google: { clientId, clientSecret },
    github: { clientId, clientSecret },   // GitHub App の Client ID / Secret
  },
  account: { accountLinking: { enabled: true, trustedProviders: ["google", "github"] } },
  databaseHooks: {
    user: { create: { before: async (user) => isAllowedEmail(user.email, allowedEmails) ? { data: user } : false } },
  },
  session: { cookieCache: { enabled: true, maxAge: 5 * 60 } },
  plugins: [nextCookies()],   // better-auth/next-js
})
```
- メール・パスワードでのログインは有効にしない
- `databaseHooks` で `false` を返すと作成が止まることを、インストール済みの better-auth の型定義かドキュメントで確認する。止まらない場合は、同じ効果のある公式の手段 (例: `hooks.before` で `/callback/` を検査する) に置き換え、どれを使ったかを報告に書く
- auth-schema は `pnpm dlx @better-auth/cli generate --config src/lib/auth/server.ts --output src/db/auth-schema.ts` で作れればそれを使う。CLI が環境変数不足などで動かない場合は、インストール済みバージョンのドキュメント (node_modules/better-auth 内) にある Drizzle スキーマ例のとおりに手で書く

## 触らない範囲
- `package.json` と lockfile
- `src/db/schema.ts` の既存テーブル (列や名前を変えない)
- `src/lib/env.ts`
- `src/app/page.tsx` などの画面 (ログイン画面は PBI-006)

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、許可リストのテストが pass する (大文字小文字・前後の空白を無視、空文字/null/undefined は false、リストにないものは false)
2. 検証コマンド 2 の出力が `4` 以上 (`user` `session` `account` `verification` の CREATE TABLE がマイグレーションにある)
3. 検証コマンド 3 が終了コード 0
4. 検証コマンド 4 が終了コード 0 (環境変数なしで build が通る)
5. 検証コマンド 5 の出力が空 (メール・パスワードのログインを有効にしていない)

## 検証コマンド
1. `pnpm test:unit src/lib/auth`
2. `cat drizzle/*.sql | grep -cE 'CREATE TABLE "(user|session|account|verification)"'`
3. `pnpm typecheck`
4. `pnpm build`
5. `grep -rn "emailAndPassword" src`

## 補足
- 環境変数は `@/lib/env` の `authEnv()` だけで読む (`process.env` を直接読まない)
- DB は `@/db/client` の `getDb()` を使う
- Next.js 16 の `headers()` は async
