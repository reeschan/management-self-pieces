# PBI-006: ログイン画面とログイン必須のレイアウト

- 担当モデル: opus (select_model.py: sensitive; scores {'novelty': 0, 'coupling': 1, 'ambiguity': 0})
- 依存: PBI-005

## 目的
ダッシュボードなどの画面はログインしていないと見られないようにする。ログイン画面には Google と GitHub のボタンを置き、許可リストで拒否されたときはその旨を表示する。

## 対象
- 新規 `src/app/login/page.tsx`: ログイン画面 (Server Component)。`searchParams` の `error` があれば「このアカウントでは利用できません」などのエラーを表示する。ボタン部分は下の client component を使う
- 新規 `src/components/auth/sign-in-buttons.tsx` (`"use client"`): 「Google でログイン」「GitHub でログイン」。`authClient.signIn.social({ provider, callbackURL: "/", errorCallbackURL: "/login?error=denied" })`
- 新規 `src/components/auth/sign-out-button.tsx` (`"use client"`): `authClient.signOut()` のあと `/login` に移動
- 新規 `src/app/(app)/layout.tsx`: `getSession()` (`@/lib/auth/server`) が null なら `redirect("/login")`。セッションがあっても `isAllowedEmail(session.user.email, authEnv().allowedEmails)` (`@/lib/auth/allowlist`、`@/lib/env`) が false なら `redirect("/login?error=denied")` (許可リストから外したユーザーの既存セッションを通さないため)。ログイン中なら、上部にユーザーのメールアドレスとログアウトボタンを持つ細いヘッダーを出し、`children` を表示する
- 移動 `src/app/page.tsx` → `src/app/(app)/page.tsx`: 中身は「ダッシュボード (準備中)」と表示するだけの仮のページに置き換える (PBI-013 で作り直す)

ログイン画面ではすでにログイン済みなら `/` に `redirect` する。

## 触らない範囲
- `src/lib/auth/` (PBI-005 の担当。呼び出すだけ)
- `src/db/`、`src/lib/env.ts`、`package.json`
- `src/app/layout.tsx` のフォントやメタデータ (タイトルを `management-self-pieces` に変える変更だけはしてよい)

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0
2. 検証コマンド 2 が終了コード 0 で、出力に `/login` が含まれる
3. 検証コマンド 3 の出力が `ok` (ルートの `src/app/page.tsx` が無く、`(app)/page.tsx` と `(app)/layout.tsx` がある)
4. 検証コマンド 4 の出力が 1 以上 (layout で未ログイン時に `/login` へ redirect している)
5. 検証コマンド 5 の出力が 1 以上 (layout でも許可リストを確認している)

## 検証コマンド
1. `pnpm typecheck`
2. `pnpm build`
3. `test ! -e src/app/page.tsx && test -f "src/app/(app)/page.tsx" && test -f "src/app/(app)/layout.tsx" && echo ok`
4. `grep -c 'redirect("/login")' "src/app/(app)/layout.tsx"`
5. `grep -c 'isAllowedEmail' "src/app/(app)/layout.tsx"`

## 補足
- 見た目は Tailwind で最低限 (中央寄せのカードとボタン 2 つ)。テーマは後で style-guide スキルで決めるので凝らない
- `(app)` はルートグループなので URL には出ない
- `getSession()` は headers を読む。下の cacheComponents の注意に従う (この layout は `export const instant = false` を付けて、サーバーでセッションを確かめてから描画する形を推奨)

### cacheComponents についての共通の注意 (PBI-003 の結果から追記)
この repo の `next.config.ts` は `cacheComponents: true` (create-next-app の既定)。次を守る。詳細は `node_modules/next/dist/docs/01-app/02-guides/migrating-to-cache-components.md` と `authentication-with-cache-components.md`。
- route segment config の `export const dynamic = ...` は使えない (build エラーになる)。`export const runtime = "nodejs"` も書かない (既定が nodejs)。`maxDuration` は build が通れば残してよい
- Route Handler は、`request` の本文やヘッダーを読めば自動でリクエスト時に動く
- page / layout で `headers()`・`cookies()`・`searchParams`・セッションを読むときは、その部分を `<Suspense>` の中のコンポーネントに置くか、その page / layout に `export const instant = false` を付ける (ガイドの「Migrating an existing app」)。どちらにしたかを報告に書く
- 事前生成される部分で `new Date()`・`Date.now()`・`Math.random()` を呼ばない
