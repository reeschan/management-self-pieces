# PBI-007: GitHub App クライアントと node.yaml の取り込み

- 担当モデル: opus (select_model.py: coupling=2; scores {'novelty': 2, 'coupling': 2, 'ambiguity': 1})
- 依存: PBI-002, PBI-003

## 目的
GitHub App を入れたリポジトリから、ルートの `node.yaml` を Installation Token で読み込み、検証済みの Node と検証エラーの一覧を作る。ユーザーのログイン状態に依存しないので、Webhook や Cron からも使える。GitHub への依存は差し替え可能な関数 (`RepoSource`) にまとめ、取り込みのロジックはテストで確かめられるようにする。

## 対象
- 新規 `src/lib/github/types.ts`
- 新規 `src/lib/github/importer.ts`
- 新規 `src/lib/github/app.ts`
- 新規 `src/lib/github/importer.test.ts`

### types.ts
```ts
export type RepoRef = { fullName: string; defaultBranch: string };   // fullName は "owner/name"
export type RepoFile = { content: string; sha: string };
export interface RepoSource {
  listRepos(): Promise<RepoRef[]>;
  getRepo(fullName: string): Promise<RepoRef | null>;                        // App が入っていなければ null
  getFile(fullName: string, path: string, ref: string): Promise<RepoFile | null>; // 無ければ null。テキストとして返す
  getRawFile(fullName: string, path: string, ref: string): Promise<{ bytes: Uint8Array } | null>; // 画像などのバイナリ用
}
export type ImportedManifest = { repo: string; sha: string; manifest: NodeManifest };
export type ImportError = { repo: string; path: string; message: string };
export type ImportResult = { manifests: ImportedManifest[]; errors: ImportError[]; scannedRepos: string[] };
```

### importer.ts
- `MANIFEST_PATH = "node.yaml"` を export
- `importAll(source: RepoSource): Promise<ImportResult>`: `listRepos()` の全リポジトリについて `importRepo` 相当を行い、結果をまとめる
- `importRepo(source: RepoSource, fullName: string): Promise<ImportResult>`: 1 リポジトリ分。`getRepo` が null なら `scannedRepos: [fullName]`・manifests/errors 空を返す (= そのリポジトリの Node は消す、という意味になる)
- `node.yaml` が無いリポジトリは何も返さない (エラーにしない)。`scannedRepos` には含める
- 解析には `parseManifest` (`@/lib/manifest/parse`) を使う。`ok: false` なら errors の各要素を 1 つの `ImportError` (`message` は `errors.join("; ")`) にする
- **id の重複**: `importAll` で同じ id が複数のリポジトリにあったら、fullName の辞書順で先のものを採用し、後のものは `message: "id '<id>' は <先のリポジトリ> と重複しています"` のエラーにする
- 1 リポジトリの読み込みが例外を投げても全体は止めず、そのリポジトリを `ImportError` (`path: "node.yaml"`) にして続ける。そのリポジトリは `scannedRepos` に**含めない** (一時的な失敗で Node を消さないため)
- `sha` は `getFile` が返す node.yaml の sha

### app.ts (本物の GitHub につなぐ)
- `createRepoSource(): RepoSource` を export。`githubEnv()` (`@/lib/env`) で App ID と秘密鍵を読み、`octokit` の `App` を使う
- `listRepos`: App の全 installation について `GET /installation/repositories` をページングで集める
- `getRepo`: `GET /repos/{owner}/{repo}/installation` で installation を取り、その installation の octokit で `GET /repos/{owner}/{repo}`。404 なら null
- `getFile`: `GET /repos/{owner}/{repo}/contents/{path}?ref=` の base64 を UTF-8 文字列にする。404 なら null
- `getRawFile`: 同じ API を `Accept: application/vnd.github.raw` で取得してバイト列にする。404 なら null
- installation ごとの octokit は同じ `createRepoSource()` の中でキャッシュしてよい

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、テストがすべて pass する。テストは偽の `RepoSource` を使い、少なくとも次を含む
   - 正しい node.yaml が 2 リポジトリにあると manifests が 2 件、sha が入る
   - node.yaml が無いリポジトリは manifests にもerrors にも出ず、scannedRepos には出る
   - 不正な node.yaml は errors に 1 件出て、message に問題の項目パスが含まれる
   - 同じ id が 2 リポジトリにあると、辞書順で先のリポジトリが採用され、後は重複エラーになる
   - `getFile` が例外を投げたリポジトリは errors に出て、scannedRepos に含まれない
   - `importRepo` で `getRepo` が null のとき scannedRepos にその名前だけが入る
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0

### cacheComponents についての共通の注意 (PBI-003 の結果から追記)
この repo の `next.config.ts` は `cacheComponents: true` (create-next-app の既定)。次を守る。詳細は `node_modules/next/dist/docs/01-app/02-guides/migrating-to-cache-components.md` と `authentication-with-cache-components.md`。
- route segment config の `export const dynamic = ...` は使えない (build エラーになる)。`export const runtime = "nodejs"` も書かない (既定が nodejs)。`maxDuration` は build が通れば残してよい
- Route Handler は、`request` の本文やヘッダーを読めば自動でリクエスト時に動く
- page / layout で `headers()`・`cookies()`・`searchParams`・セッションを読むときは、その部分を `<Suspense>` の中のコンポーネントに置くか、その page / layout に `export const instant = false` を付ける (ガイドの「Migrating an existing app」)。どちらにしたかを報告に書く
- 事前生成される部分で `new Date()`・`Date.now()`・`Math.random()` を呼ばない
