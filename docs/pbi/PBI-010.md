# PBI-010: TrackerProvider インターフェースと Asana の実装

- 担当モデル: opus (select_model.py: sensitive)
- 依存: PBI-002

## 目的
チケット管理の連携先を差し替えられるよう、`TrackerProvider` インターフェースを定め、最初の実装として Asana (PAT) を作る。Node と Asana プロジェクトは 1 対 1 で、**プロジェクトの説明 (notes) に `piece-node-id: <node id>` の行を書く**。これにより DB が消えても、Asana を検索して Node との対応を作り直せる。

## 対象
- 新規 `src/lib/tracker/types.ts`
- 新規 `src/lib/tracker/marker.ts`
- 新規 `src/lib/tracker/asana.ts`
- 新規 `src/lib/tracker/tracker.test.ts`

### types.ts
```ts
export type ExternalRef = { provider: string; externalId: string; url: string | null };
export type TrackerTask = { externalId: string; name: string; completed: boolean; dueOn: string | null; url: string | null };
export type TaskInput = { name: string; notes?: string; dueOn?: string };   // dueOn は YYYY-MM-DD
export type NodeSummary = { id: string; title: string; summary: string };
export interface TrackerProvider {
  readonly id: string;                                               // "asana"
  findProjectByNodeId(nodeId: string): Promise<ExternalRef | null>;
  createProject(node: NodeSummary): Promise<ExternalRef>;
  listTasks(projectId: string): Promise<TrackerTask[]>;
  createTask(projectId: string, input: TaskInput): Promise<TrackerTask>;
  createWebhook(projectId: string, targetUrl: string): Promise<{ webhookId: string }>;
}
```

### marker.ts
- `buildProjectNotes(node: NodeSummary): string` → `"<summary>\n\npiece-node-id: <id>"`
- `extractNodeId(notes: string | null | undefined): string | null` → notes の中の `piece-node-id: <id>` の行から id を取り出す (行頭・行末の空白を許す。id は `[a-z0-9-]+`)。無ければ null

### asana.ts
`createAsanaProvider(opts: { pat: string; workspaceGid: string; teamGid?: string; fetch?: typeof fetch }): TrackerProvider`
- ベース URL `https://app.asana.com/api/1.0`。ヘッダー `Authorization: Bearer <pat>`、`Accept: application/json`。本文がある場合は `Content-Type: application/json` で `{ "data": {...} }`
- 応答が 2xx 以外なら `AsanaError` (export する。`status` を持つ) を投げる。メッセージに PAT を含めない
- `findProjectByNodeId`: `GET /projects?workspace=<gid>&opt_fields=name,notes,permalink_url&limit=100` を `next_page.offset` でページングし、`extractNodeId(notes) === nodeId` の最初のプロジェクトを返す
- `createProject`: `POST /projects` に `{ name: node.title, notes: buildProjectNotes(node), workspace, team? }` (teamGid があるときだけ team を付ける)、`opt_fields=permalink_url`
- `listTasks`: `GET /projects/<gid>/tasks?opt_fields=name,completed,due_on,permalink_url&limit=100` をページングして全件
- `createTask`: `POST /tasks` に `{ name, notes?, due_on?, projects: [projectId] }`、`opt_fields=name,completed,due_on,permalink_url`
- `createWebhook`: `POST /webhooks` に `{ resource: projectId, target: targetUrl }`。応答の `data.gid` を webhookId にする
- `url` は `permalink_url` (無ければ null)

## 触らない範囲
- `src/lib/env.ts` (asana.ts は env を読まない。呼び出し側が値を渡す)
- `src/db/`、`src/app/`、`package.json`

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、テストがすべて pass する。テストは偽の `fetch` を渡し、少なくとも次を含む
   - `buildProjectNotes` → `extractNodeId` で id が戻る。marker の無い notes や null で null
   - `findProjectByNodeId` が 2 ページ目 (offset 付き) にあるプロジェクトを見つける。リクエスト URL に `workspace=` と `offset=` が含まれる
   - `createProject` の本文に notes の marker が含まれ、teamGid を渡したときだけ `team` が入る
   - `listTasks` がページングして全件を返し、`due_on` → `dueOn`、`permalink_url` → `url` に写す
   - `createTask` の本文の `projects` に projectId が入る
   - 401 応答で `AsanaError` (status 401) が投げられ、メッセージに PAT の文字列が含まれない
   - すべてのリクエストに `Authorization: Bearer <pat>` が付く
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0
