# PBI-011: Asana の Webhook 受信・タスク同期・Server Actions

- 担当モデル: opus (select_model.py: sensitive; scores {'novelty': 1, 'coupling': 2, 'ambiguity': 0})
- 依存: PBI-004, PBI-005, PBI-010

## 目的
Node に Asana プロジェクトをつなぎ、タスクを DB (`task_cache`) に一時保存して表示できるようにする。Asana 側でタスクが変わったら Webhook で受け取って取り直す。画面からは Server Actions で「プロジェクトを作成 (または既存とつなぐ)」「タスクを作成」「タスクを取り直す」を呼べるようにする。Webhook は公開 URL なので、**ハンドシェイクで受け取った secret による署名検証**を必ず行う。

## 対象
- 新規 `src/lib/tracker/signature.ts`: `verifyAsanaSignature(secret: string, rawBody: string, signature: string | null): boolean` (HMAC-SHA256 の hex と定数時間で比較。null や長さ違いは false)
- 新規 `src/lib/tracker/signature.test.ts`
- 新規 `src/lib/tracker/service.ts`
- 新規 `src/app/api/webhooks/asana/route.ts`
- 新規 `src/app/(app)/actions.ts` (`"use server"`)

### service.ts
`getTracker()` は `asanaEnv()` から `createAsanaProvider` を作って返す。DB は `getDb()`。

- `linkNodeToAsana(nodeId: string): Promise<ExternalRef>`
  1. `external_refs` に (nodeId, "asana") があればそれを返す
  2. nodes に nodeId が無ければ `Error("node not found")`
  3. `findProjectByNodeId(nodeId)` → 無ければ `createProject({ id, title, summary })`
  4. `external_refs` に insert
  5. `sync_state` に key `asana:webhook-pending:<projectId>`、値に現在時刻 (ISO 文字列) を upsert してから、`createWebhook(projectId, "<appUrl>/api/webhooks/asana?project=<projectId>")` を呼ぶ。失敗したら (例: 既に Webhook がある) `console.warn` に記録して続ける (例外は外に出さない)
  6. `refreshTasks(nodeId)` を呼び、ref を返す
- `refreshTasks(nodeId: string): Promise<number>`: ref が無ければ 0。`listTasks` の結果で、その project の `task_cache` を**削除してから insert** (`db.batch`)。件数を返す
- `refreshTasksByProject(projectId: string): Promise<number>`: `external_refs` から nodeId を引いて `refreshTasks` (見つからなければ 0)
- `createTaskForNode(nodeId: string, input: TaskInput): Promise<TrackerTask>`: ref が無ければ `Error("not linked")`。作成後に `refreshTasks`

### api/webhooks/asana/route.ts (`POST`)
1. クエリ `project` が無ければ 400
2. ヘッダー `x-hook-secret` があるとき (ハンドシェイク): `sync_state` に key `asana:webhook-secret:<project>` で値を upsert し、**同じ値を `X-Hook-Secret` ヘッダーに付けて** 200 を返す
   - 受け付けるのは、`asana:webhook-pending:<project>` があり、その時刻が 5 分以内のときだけ。受け付けたら pending の行を削除する。pending が無い・古い、またはすでに secret が保存されている project へのハンドシェイクは 409 を返し、何も保存しない (第三者が secret を登録・差し替えできないように)
3. それ以外: 保存済みの secret を読み、無ければ 401。`verifyAsanaSignature(secret, rawBody, x-hook-signature)` が false なら 401
4. 検証が通れば `refreshTasksByProject(project)` を実行して 200 (`events` の中身は見ない。変更があったら全部取り直す)
- 本文は `await req.text()` で生のまま読み、検証より前に JSON.parse しない

### (app)/actions.ts
- `linkAsanaProject(nodeId: string)`、`createTask(nodeId: string, input: TaskInput)`、`refreshNodeTasks(nodeId: string)` を export
- どれも最初に `getSession()` を確認し、null なら `Error("unauthorized")` を投げる
- 入力は Zod で検証する (nodeId は node.yaml の id と同じ形式、`name` は 1〜200 文字、`dueOn` は `YYYY-MM-DD` 任意)
- 処理後に `revalidatePath("/")`

## 補足
- Asana のハンドシェイクは Webhook を作るリクエスト (`createWebhook`) の処理中に、別のリクエストとして届く
- `task_cache` の `provider` は `"asana"`、`projectExternalId` は project の gid
- エラーの応答に秘密の値を含めない

### cacheComponents についての共通の注意 (PBI-003 の結果から追記)
この repo の `next.config.ts` は `cacheComponents: true` (create-next-app の既定)。次を守る。詳細は `node_modules/next/dist/docs/01-app/02-guides/migrating-to-cache-components.md` と `authentication-with-cache-components.md`。
- route segment config の `export const dynamic = ...` は使えない (build エラーになる)。`export const runtime = "nodejs"` も書かない (既定が nodejs)。`maxDuration` は build が通れば残してよい
- Route Handler は、`request` の本文やヘッダーを読めば自動でリクエスト時に動く
- page / layout で `headers()`・`cookies()`・`searchParams`・セッションを読むときは、その部分を `<Suspense>` の中のコンポーネントに置くか、その page / layout に `export const instant = false` を付ける (ガイドの「Migrating an existing app」)。どちらにしたかを報告に書く
- 事前生成される部分で `new Date()`・`Date.now()`・`Math.random()` を呼ばない
