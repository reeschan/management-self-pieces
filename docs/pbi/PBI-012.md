# PBI-012: 開発用のサンプル Node と seed スクリプト

- 担当モデル: sonnet (select_model.py: files_changed=8 >= 4; scores {'novelty': 0, 'coupling': 0, 'ambiguity': 0})
- 依存: PBI-008

## 目的
GitHub App を用意する前でも、ダッシュボードの見た目を確かめられるようにする。`fixtures/` に node.yaml のサンプルを置き、`pnpm db:seed` で取り込みと同じ経路 (`applyImportResult`) を通して DB に入れる。サンプルは node.yaml の書き方の例も兼ねる。

## 対象
- 新規 `fixtures/*.yaml` (6 件)
- 新規 `scripts/seed.mts`
- 新規 `scripts/fixtures.test.ts`

### fixtures (ファイル名は `<id>.yaml`)
持ち主の実際の成果物を題材にする。kind が偏らないようにし、relations で互いにつなぐ。
| id | kind | 内容 |
|---|---|---|
| `my-portfolio-second` | app | 個人ポートフォリオ (Next.js / Vercel、three.js の 3D 背景、AI チャット) |
| `ai-session-knowledge-viewer` | app | Claude Code / Codex の会話ログを要約・分類して閲覧する Next.js アプリ |
| `agentcron` | app | Cron 式でローカルの AI エージェントを起動する Go 製の常駐スケジューラ |
| `style-guide-skill` | skill | 自由記述から UI テーマ (Tailwind v4 theme.css) を作る Claude Code スキル。`uses` → `jev-client` |
| `jev-client` | library | Jev (判定 API) の共通クライアント (Python / JS) |
| `management-self-pieces` | app | このアプリ。`related` → `my-portfolio-second` |

- 少なくとも 1 件は `status: maintenance`、1 件は `diagrams` と `links` と `tags` と `meta` を持つ
- `pbi-orchestration-jev` のような未登録の id への relation を 1 件入れてよい (相手が無くても壊れないことの確認)
- 各ファイルの 1 行目に `# yaml-language-server: $schema=../src/app/schema/node.json` は書かない (route なのでパスが無い)。代わりにコメントで「このファイルは node.yaml の例」と書く

### scripts/seed.mts
- `fixtures/*.yaml` を読み、`parseManifest` で検証し、`ImportResult` (`repo` は `fixtures/<ファイル名>`、`sha` は `"fixture"`、`scannedRepos` は全ファイルの `fixtures/<ファイル名>`) を作って `applyImportResult(getDb(), result)` に渡す
- 検証に失敗したファイルがあれば内容を表示して終了コード 1
- 結果の `SyncSummary` を表示する
- `DATABASE_URL` が無いときは `dbEnv()` の `EnvError` のメッセージを表示して終了コード 1 (スタックは出さない)

### scripts/fixtures.test.ts
- `fixtures/*.yaml` のすべてが `parseManifest` で `ok: true` になることを確かめる
- すべての id がファイル名と一致することを確かめる

## 触らない範囲
- `src/` 配下すべて (呼び出すだけ)
- `package.json` (`db:seed` スクリプトは PBI-001 で追加済み)

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、fixtures のテストが pass する
2. 検証コマンド 2 の出力が `6`
3. 検証コマンド 3 の出力に `DATABASE_URL` と `exit=1` が含まれ、スタックトレース (`    at ` で始まる行) が含まれない (DB 無しでは分かりやすく失敗する)
4. 検証コマンド 4 が終了コード 0

## 検証コマンド
1. `pnpm test:unit scripts/fixtures.test.ts`
2. `ls fixtures/*.yaml | wc -l`
3. `env -u DATABASE_URL pnpm exec tsx scripts/seed.mts; echo "exit=$?"`
4. `pnpm typecheck`

## 補足
- `tsx` は `@/*` の import alias を tsconfig から解決できる。解決できなければ相対パスで import する
- 検証コマンド 3 は `.env.local` を読まない形で実行している (`pnpm db:seed` は `.env.local` を読む)
