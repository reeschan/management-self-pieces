# PBI-013: 3D ダッシュボード (Node が空間に浮かぶグラフ)

- 担当モデル: sonnet (select_model.py: novelty・coupling・ambiguity のどれかが 1 以上; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 1})
- 依存: PBI-006, PBI-008

## 目的
アプリの中心の画面。Node を 3D 空間に浮かぶ球として表示し、relations を線でつなぐ。色は kind、大きさは未完了のタスク数、archived は薄く表示する。Node を押すとカメラが寄り、選んだ Node の id を親に伝える (詳細パネルは PBI-015)。

## 対象
- 新規 `src/lib/dashboard/graph.ts`: 純粋関数 `toGraphData`
- 新規 `src/lib/dashboard/graph.test.ts`
- 新規 `src/lib/dashboard/load.ts`: `loadGraph()` (DB から読んで `toGraphData` に渡す)
- 新規 `src/components/graph/graph-3d.tsx` (`"use client"`): react-force-graph-3d の描画
- 新規 `src/components/graph/dashboard.tsx` (`"use client"`): 画面全体。graph-3d を `next/dynamic` の `ssr: false` で読み込む。選択中の id を state で持つ
- 変更 `src/app/(app)/page.tsx`: 仮のページを置き換え、`loadGraph()` の結果を `Dashboard` に渡す

### graph.ts
```ts
export type GraphNode = { id: string; kind: string; title: string; summary: string; status: string; openTasks: number; color: string; val: number };
export type GraphLink = { source: string; target: string; type: string };
export type GraphData = { nodes: GraphNode[]; links: GraphLink[] };
export function toGraphData(
  nodes: { id: string; kind: string; title: string; summary: string; status: string }[],
  relations: { fromId: string; toId: string; type: string }[],
  openTaskCounts: Record<string, number>,
): GraphData;
export const kindColors: Record<string, string>;   // kinds.ts の全 kind に色を割り当てる。未知の kind は other の色
```
- 両端の Node が存在しない link は捨てる
- `val` (球の大きさ) = `1 + Math.min(openTasks, 20) / 4`
- `color` は `kindColors[kind]`。status が `archived` なら色を半透明にする (例: `#rrggbb` に `66` を足した 8 桁)

### load.ts
- nodes 全件、relations 全件、`task_cache` の `completed = false` を node_id ごとに数えたものを読み、`toGraphData` に渡す

### graph-3d.tsx
- props: `data: GraphData`、`selectedId: string | null`、`onSelect(id: string | null): void`
- ノードのラベル (hover) は title と kind
- link は `type` によって色を変えず、細い線 + 進む向きの小さな粒 (`linkDirectionalParticles`) で向きを見せる
- ノードをクリックしたら、そのノードの位置へカメラを寄せ (`cameraPosition` を 1 秒で)、`onSelect(id)`。背景をクリックしたら `onSelect(null)`
- 選択中のノードは少し大きく・明るく表示する
- コンテナの大きさに合わせて width/height を更新する (ResizeObserver)

### dashboard.tsx
- graph-3d を画面いっぱいに表示する
- 左上に、kind ごとの色の凡例と件数
- Node が 0 件のときは、グラフの代わりに「Node がありません。`pnpm db:seed` でサンプルを入れるか、GitHub App を入れたリポジトリに node.yaml を置いてください」と表示する
- 選択中の id は PBI-015 で使うので、右側に `selectedId` があるときだけ表示する空の領域 (`<aside data-testid="node-panel-slot">`) を置いておく

## 補足
- react-force-graph-3d は `window` を参照するので、必ず `next/dynamic` の `ssr: false` で読み込む
- 見た目のテーマは後で style-guide スキルで決める。いまは暗い背景 (`#05060a` 程度) と kind の色だけでよい
- ノード数は数十件を想定。性能の工夫は不要

### cacheComponents についての共通の注意 (PBI-003 の結果から追記)
この repo の `next.config.ts` は `cacheComponents: true` (create-next-app の既定)。次を守る。詳細は `node_modules/next/dist/docs/01-app/02-guides/migrating-to-cache-components.md` と `authentication-with-cache-components.md`。
- route segment config の `export const dynamic = ...` は使えない (build エラーになる)。`export const runtime = "nodejs"` も書かない (既定が nodejs)。`maxDuration` は build が通れば残してよい
- Route Handler は、`request` の本文やヘッダーを読めば自動でリクエスト時に動く
- page / layout で `headers()`・`cookies()`・`searchParams`・セッションを読むときは、その部分を `<Suspense>` の中のコンポーネントに置くか、その page / layout に `export const instant = false` を付ける (ガイドの「Migrating an existing app」)。どちらにしたかを報告に書く
- 事前生成される部分で `new Date()`・`Date.now()`・`Math.random()` を呼ばない
