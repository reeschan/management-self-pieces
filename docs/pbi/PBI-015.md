# PBI-015: Node の詳細パネル (概要 / 詳細 / アーキ図 / チケット / リンク)

- 担当モデル: sonnet (select_model.py: novelty・coupling・ambiguity のどれかが 1 以上; scores {'novelty': 0, 'coupling': 1, 'ambiguity': 1})
- 依存: PBI-011, PBI-013, PBI-014

## 目的
ダッシュボードで Node を押したときに右側に開くパネルを作る。タブで「概要・詳細・アーキ図・チケット・リンク」を切り替える。チケットのタブからは Asana プロジェクトの作成 (つなぐ)・タスクの作成・取り直しができる。

## 対象
- 新規 `src/components/panel/node-panel.tsx` (`"use client"`): パネル本体とタブ
- 新規 `src/components/panel/tickets-tab.tsx` (`"use client"`): チケットのタブ
- 新規 `src/components/panel/diagram-view.tsx` (`"use client"`): 図 1 枚の表示 (画像 / Mermaid)
- 変更 `src/components/graph/dashboard.tsx`: `node-panel-slot` の aside に `NodePanel` を入れる

### node-panel.tsx
- props: `nodeId: string`、`onClose(): void`
- `nodeId` が変わるたびに `GET /api/nodes/<id>` を取得する (読み込み中・エラー・404 の表示を持つ)。古いリクエストの結果で上書きしない (AbortController)
- ヘッダー: タイトル、kind、status、閉じるボタン (Esc キーでも閉じる)
- タブ (role="tablist" / "tab" / "tabpanel" と aria-selected を付ける):
  - **概要**: summary、tags、更新日時、取り込み元 (sourceRepo)。importErrors があれば警告として表示
  - **詳細**: `react-markdown` + `remark-gfm` で Markdown を表示。markdown が null なら「詳細を読み込めませんでした (<path>)」。生の HTML は描画しない (rehype-raw を使わない)
  - **アーキ図**: diagrams を `DiagramView` で縦に並べる。0 件なら「node.yaml の diagrams に図を追加すると表示されます」
  - **チケット**: `TicketsTab`
  - **リンク**: links を「名前: URL」の一覧で表示 (`target="_blank" rel="noopener noreferrer"`)。0 件なら空の表示

### tickets-tab.tsx
- props: `nodeId`、`asana`、`tasks`、`onChanged(): void` (再取得のため)
- `asana` が null: 「Asana プロジェクトを作成してつなぐ」ボタン → Server Action `linkAsanaProject(nodeId)`
- つながっている: Asana のプロジェクトへのリンク、「取り直す」ボタン (`refreshNodeTasks`)、未完了 / 完了済みの件数、タスク一覧 (完了済みは打ち消し線、期限、Asana へのリンク)、新しいタスクの入力 (名前と期限) → `createTask`
- 処理中はボタンを無効にし、失敗したらメッセージを表示する (`useTransition` を使う)
- 成功したら `onChanged()`

### diagram-view.tsx
- props: `{ title, kind, url }`
- svg / png / jpeg / webp: `<img src={url} alt={title ?? path}>` (クリックで別タブに原寸を開く)
- mermaid: `url` からテキストを取得し、`mermaid` を動的 import して `mermaid.render` で SVG にして表示する。`securityLevel: "strict"`、テーマは dark
- markdown は対象外 (表示しない)

## 補足
- タブのラベルは検証コマンド 3 のため、ダブルクォートの文字列リテラル (`"概要"` など) で書く
- Mermaid の SVG を差し込むのに `dangerouslySetInnerHTML` を使ってよいのは diagram-view.tsx だけ (mermaid の strict モードで消毒された出力に限る)
- 見た目は Tailwind で最低限。幅は 420px 程度、画面右に固定、中身はスクロール

### cacheComponents についての共通の注意 (PBI-003 の結果から追記)
この repo の `next.config.ts` は `cacheComponents: true` (create-next-app の既定)。次を守る。詳細は `node_modules/next/dist/docs/01-app/02-guides/migrating-to-cache-components.md` と `authentication-with-cache-components.md`。
- route segment config の `export const dynamic = ...` は使えない (build エラーになる)。`export const runtime = "nodejs"` も書かない (既定が nodejs)。`maxDuration` は build が通れば残してよい
- Route Handler は、`request` の本文やヘッダーを読めば自動でリクエスト時に動く
- page / layout で `headers()`・`cookies()`・`searchParams`・セッションを読むときは、その部分を `<Suspense>` の中のコンポーネントに置くか、その page / layout に `export const instant = false` を付ける (ガイドの「Migrating an existing app」)。どちらにしたかを報告に書く
- 事前生成される部分で `new Date()`・`Date.now()`・`Math.random()` を呼ばない
