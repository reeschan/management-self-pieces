# PBI-016: README・セットアップ手順・node.yaml の例

- 担当モデル: haiku (select_model.py: どの条件にも当たらない; scores {'novelty': 0, 'coupling': 0, 'ambiguity': 0})

## 目的
持ち主がこのアプリを Vercel に載せ、各リポジトリに node.yaml を置いて使い始められるよう、手順をまとめる。外部サービス (Neon・Google・GitHub App・Asana・Vercel) の設定は手作業になるので、何をどこに設定するかを漏れなく書く。

## 対象
- 置き換え `README.md` (create-next-app が作ったものを置き換える)
- 新規 `docs/SETUP.md`
- 新規 `examples/node.yaml`

### README.md
- 1 段落の概要 (docs/DESIGN.md の冒頭を元に)
- 主な機能 (3D ダッシュボード、詳細パネル、Asana 連携、GitHub からの自動取り込み)
- ローカルでの起動: `pnpm install` → `.env.local` を `.env.example` から作る → `pnpm db:migrate` → `pnpm db:seed` → `pnpm dev`

- 関連文書へのリンク: `docs/SETUP.md`、`docs/DESIGN.md`、`docs/TODO.md`

### docs/SETUP.md
次の見出しで、それぞれ手順と、`.env` のどのキーに何を入れるかを書く。
1. **Neon**: Vercel の Marketplace から Neon を追加 → `DATABASE_URL`。`pnpm db:migrate` の実行
2. **Better Auth**: `BETTER_AUTH_SECRET` の作り方 (`openssl rand -base64 32`)、`APP_URL`、`ALLOWED_EMAILS`
3. **Google OAuth**: Google Cloud Console で OAuth クライアント (ウェブアプリ) を作る。承認済みリダイレクト URI は `<APP_URL>/api/auth/callback/google` (ローカル用に `http://localhost:3000/api/auth/callback/google` も)
4. **GitHub App**: 作成画面での設定
   - Callback URL: `<APP_URL>/api/auth/callback/github`
   - Webhook URL: `<APP_URL>/api/webhooks/github`、Webhook secret → `GITHUB_WEBHOOK_SECRET`
   - Repository permissions: Contents: Read-only、Metadata: Read-only
   - Account permissions: Email addresses: Read-only
   - Subscribe to events: Push (installation / installation_repositories はアプリの既定で届く)
   - App ID → `GITHUB_APP_ID`、Client ID / Secret → `GITHUB_APP_CLIENT_ID` / `GITHUB_APP_CLIENT_SECRET`、秘密鍵 (.pem) → `GITHUB_APP_PRIVATE_KEY` (改行を `\n` にして 1 行で入れてよい)
   - 自分のアカウントに App をインストールし、対象のリポジトリを選ぶ
5. **Asana**: 個人アクセストークン → `ASANA_PAT`。ワークスペースの GID の調べ方 (`GET https://app.asana.com/api/1.0/workspaces`) → `ASANA_WORKSPACE_GID`。組織のワークスペースならチームの GID → `ASANA_TEAM_GID`。Webhook はアプリが Node をつなぐときに自動で作る
6. **Vercel**: リポジトリを Import → 上の環境変数をすべて設定 → `CRON_SECRET` を設定 (Cron が使う) → デプロイ。Hobby プランの Cron は 1 日 1 回
7. **各リポジトリに node.yaml を置く**: `examples/node.yaml` をコピーし、1 行目のコメントでエディタの補完が効くことを説明
8. **困ったとき**: 取り込みエラーはダッシュボードの Node の概要タブに出る / 手動で全部取り込み直すには `curl -H "Authorization: Bearer $CRON_SECRET" <APP_URL>/api/cron/import` / Asana の Webhook を作り直すには `sync_state` の `asana:webhook-secret:<project gid>` を消してからつなぎ直す

1. `pnpm exec tsx -e "import {readFileSync} from 'node:fs';import {parseManifest} from './src/lib/manifest/parse';const r=parseManifest(readFileSync('examples/node.yaml','utf8'));console.log(r.ok?'ok':JSON.stringify(r.errors))"`
2. `grep -oE '^[A-Z_]+=' .env.example | tr -d '=' | while read k; do grep -q "$k" docs/SETUP.md || echo "$k"; done | wc -l`
3. `grep -q "docs/SETUP.md" README.md && grep -q "docs/DESIGN.md" README.md && grep -q "docs/TODO.md" README.md && echo ok`

### cacheComponents についての共通の注意 (PBI-003 の結果から追記)
この repo の `next.config.ts` は `cacheComponents: true` (create-next-app の既定)。次を守る。詳細は `node_modules/next/dist/docs/01-app/02-guides/migrating-to-cache-components.md` と `authentication-with-cache-components.md`。
- route segment config の `export const dynamic = ...` は使えない (build エラーになる)。`export const runtime = "nodejs"` も書かない (既定が nodejs)。`maxDuration` は build が通れば残してよい
- Route Handler は、`request` の本文やヘッダーを読めば自動でリクエスト時に動く
- page / layout で `headers()`・`cookies()`・`searchParams`・セッションを読むときは、その部分を `<Suspense>` の中のコンポーネントに置くか、その page / layout に `export const instant = false` を付ける (ガイドの「Migrating an existing app」)。どちらにしたかを報告に書く
- 事前生成される部分で `new Date()`・`Date.now()`・`Math.random()` を呼ばない
