# PBI-017: node.yaml が検証エラーのとき、既存の Node を消さない

- 担当モデル: opus (select_model.py: sensitive)
- 依存: PBI-008

## 目的
PBI-008 の `planSync` は、取り込んだ範囲 (`scopeRepos`) にあって manifests に無い既存 Node を削除する。node.yaml を書き間違えて検証エラーになったリポジトリも scopeRepos に入るため、書き間違い 1 つでその Node が消え、cascade で Asana との対応 (`external_refs`) も消えてしまう。**検証エラーが出たリポジトリの既存 Node は、直されるまで前の内容のまま残す**ようにする。

## 対象
- 変更 `src/lib/import/plan.ts` の `planSync`
- 変更 `src/lib/import/plan.test.ts`

変更内容:
- `result.errors` に出たリポジトリ (`e.repo`) の集合を作り、`sourceRepo` がその集合に含まれる既存 Node は `deleteIds` に入れない
- それ以外の振る舞い (upserts、relations、errors、scopeRepos、範囲外を消さない) は変えない

## 触らない範囲
- `src/lib/import/apply.ts`、`src/lib/import/run.ts`
- `src/lib/github/`、`src/db/`、`package.json`

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0 で、テストがすべて pass する。既存の 7 件に加えて次の 2 件がある
   - scopeRepos 内で manifests に無く、`result.errors` にそのリポジトリのエラーがある既存 Node は deleteIds に入らない
   - 同じ状況でエラーが無ければ、従来どおり deleteIds に入る
2. 検証コマンド 2 が終了コード 0

## 検証コマンド
1. `pnpm test:unit src/lib/import`
2. `pnpm typecheck`

## 補足
- id の重複エラー (PBI-007 の importAll が出す) も `result.errors` に入るので、重複で負けたリポジトリの既存 Node も消えなくなる。これは意図どおり (次に直されるまで残す)
