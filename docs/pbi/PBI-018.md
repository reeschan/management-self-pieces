# PBI-018: seed から GitHub クライアントへの依存を外す

- 担当モデル: sonnet (select_model.py)
- 依存: PBI-012

## 目的
`scripts/seed.mts` は `@/lib/import/run` の `applyImportResult` を使うが、`run.ts` は `@/lib/github/app` 経由で ESM 専用の `octokit` を読み込む。tsx では解決できないため、seed.mts は `NODE_OPTIONS=--conditions=import` を付けて自分自身を起動し直す回避策を入れている。`applyImportResult` を GitHub に依存しないファイルへ移し、回避策をなくす。

## 対象
- 新規 `src/lib/import/apply-result.ts`: `SyncSummary` 型と `applyImportResult(db, result)` を `src/lib/import/run.ts` からそのまま移す (中身は変えない)。import してよいのは `@/db/client` (型)、`@/db/schema`、`@/lib/github/types` (型のみ)、`./apply`、`./plan` だけ
- 変更 `src/lib/import/run.ts`: `applyImportResult` と `SyncSummary` を `./apply-result` から import して使う。外部から使われている名前を保つため、`export { applyImportResult, type SyncSummary } from "./apply-result"` で再 export する
- 変更 `scripts/seed.mts`: 自分自身を起動し直す処理 (`spawnSync` と `NODE_OPTIONS` の分岐) を削除し、`src/` からの import をすべて静的 import にする。`applyImportResult` は `@/lib/import/apply-result` から import する

## 触らない範囲
- `src/lib/import/plan.ts`・`apply.ts` の中身
- `src/lib/github/`、`src/app/`、`src/db/`、`package.json`、`fixtures/`

## 受け入れ条件
1. 検証コマンド 1 の出力に `DATABASE_URL` と `exit=1` が含まれ、`    at ` で始まる行が含まれない
2. 検証コマンド 2 の出力が空 (seed.mts に再起動の処理が残っていない)
3. 検証コマンド 3 の出力が空 (apply-result.ts が GitHub のクライアントを import していない)
4. 検証コマンド 4 が終了コード 0 (既存のテストがすべて pass)
5. 検証コマンド 5 が終了コード 0

## 検証コマンド
1. `env -u DATABASE_URL pnpm exec tsx scripts/seed.mts; echo "exit=$?"`
2. `grep -nE "spawnSync|conditions=import" scripts/seed.mts`
3. `grep -nE "github/app|octokit" src/lib/import/apply-result.ts`
4. `pnpm test:unit`
5. `pnpm typecheck`

## 補足
- `@/lib/github/types` は `import type` で読む (実行時の依存にならない)
- `run.ts` を import している他のファイル (webhook・cron の route) は変えなくて済むように、再 export を残す
