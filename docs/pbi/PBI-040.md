# PBI-040: 動作モード (ローカル / ホスト) の判定と、localhost だけで待ち受ける起動スクリプト

- 担当モデル: codex high（sonnet 相当） (select_model.py: 決定: sonnet。novelty・coupling・ambiguity のどれかが 1 以上（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 0})
- 依存: なし

## 目的
MCP の口は、アプリがどこで動いているかで守り方を変える。持ち主の PC で明示的に有効にしたときは「ローカル」、それ以外 (Vercel を含む) は「ホスト」。この判定を 1 か所に置き、どこからでも同じ答えを得られるようにする。あわせて、ローカルで動かすときに LAN から見えないよう、`127.0.0.1` だけで待ち受ける起動スクリプトを足す。

## 対象
- 変更 `src/lib/env.ts`: 関数 `runtimeMode(source: EnvSource = process.env): "local" | "host"` を足して export する
  - `source.LOCAL_AGENT_FEATURES === "1"` で、かつ `source.VERCEL` が未設定または空文字のときだけ `"local"` を返す
  - それ以外はすべて `"host"` を返す (`"true"` や `"yes"` もホスト扱い。`VERCEL` が `"1"` ならフラグがあってもホスト)
  - 例外を投げない (ほかの `*Env()` と違い、検証失敗の概念が無い)
  - 関数の上に 1〜3 行の日本語コメントで意図 (Vercel では何があってもローカルにしない) を書く
- 変更 `src/lib/env.test.ts`: `runtimeMode` のテストを足す (下の受け入れ条件 1 の 5 ケースを含める)
- 変更 `package.json`: scripts に `"dev:local": "next dev -H 127.0.0.1"` を足す (ほかの scripts は変えない)
- 変更 `.env.example`: 末尾に次の 2 行を足す
  ```
  # ローカル機能を有効にする (1 のときだけ。Vercel では無視される)。有効にするときは pnpm dev:local で起動する
  LOCAL_AGENT_FEATURES=
  ```

## 触らない範囲
- `src/lib/env.ts` の既存の関数とスキーマ
- `src/lib/env.test.ts` の既存のテスト
- `package.json` の dependencies / devDependencies と既存の scripts

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。テストは少なくとも次の 5 ケースを含む: `{}` → host、`{LOCAL_AGENT_FEATURES:"1"}` → local、`{LOCAL_AGENT_FEATURES:"1", VERCEL:"1"}` → host、`{LOCAL_AGENT_FEATURES:"true"}` → host、`{LOCAL_AGENT_FEATURES:"1", VERCEL:""}` → local
2. 検証コマンド 2 の出力が `1`
3. 検証コマンド 3 の出力が `1`
4. 検証コマンド 4 が終了コード 0
5. 検証コマンド 5 が終了コード 0

## 検証コマンド
1. `pnpm vitest run src/lib/env.test.ts`
2. `grep -c '"dev:local": "next dev -H 127.0.0.1"' package.json`
3. `grep -c '^LOCAL_AGENT_FEATURES=$' .env.example`
4. `pnpm typecheck`
5. `pnpm lint`

## 補足
- 既存の `env.ts` は「読み込み時には検証せず、関数を呼んだときに読む」流儀。`runtimeMode` もモジュールの読み込み時に `process.env` を読まない (引数の既定値で読むのは呼び出し時なので可)
- 既存のテストの書き方 (`env.test.ts`) に合わせ、`source` を引数で渡してテストする
- コメントと文言は日本語。コミットはしない
