# PBI-041: 依存の追加と、PGlite でマイグレーション済みの DB を作るテスト用の土台

- 担当モデル: agy claude-opus-5-5-high（opus 相当） (select_model.py: 決定: opus。coupling=2; scores {'novelty': 2, 'coupling': 2, 'ambiguity': 0})
- 依存: PBI-040 (同じ package.json を触るため、その後に行う)

## 目的
MCP の口のテストでは、本番と同じ Drizzle のスキーマとクエリを、メモリ上の Postgres (PGlite) で動かして確かめる。本番の DB クライアントは neon-http (`drizzle-orm/neon-http`) で、PGlite (`drizzle-orm/pglite`) とは型が違う。そこで、両方を受け取れる共通の型 `AppDb` を作り、新しく書くデータの読み書きはこの型を引数に取るようにする。あわせて、M1 で使う依存をここでまとめて入れる。

## 対象
- 変更 `package.json` / `pnpm-lock.yaml` (pnpm で入れる。手で編集しない)
  - `pnpm add @modelcontextprotocol/sdk@1.32.1 @vercel/functions`
  - `pnpm add -D @electric-sql/pglite`
- 新規 `src/db/types.ts`
  - `AppDb` 型を export する: `PgDatabase<PgQueryResultHKT, typeof schema>` (`drizzle-orm/pg-core` の型)。`schema` は `src/db/client.ts` と同じく `./schema` と `./auth-schema` を合わせたもの
  - `getDb()` の戻り値 (neon-http) と、PGlite の drizzle インスタンスの両方が `AppDb` に代入できること (受け入れ条件 3 で確かめる)
  - 1〜2 行のコメント: 「neon-http には transaction が無く、PGlite には batch が無い。AppDb を受け取る関数では、どちらも使わず 1 文で済む書き方にする」
- 新規 `src/test/pglite.ts`
  - `export async function createTestDb(): Promise<{ db: AppDb; close(): Promise<void> }>`
  - 新しい `PGlite()` (メモリ上) を作り、`drizzle({ client, schema })` で包み、`drizzle-orm/pglite/migrator` の `migrate(db, { migrationsFolder: <リポジトリの drizzle フォルダの絶対パス> })` で全マイグレーションを適用して返す
  - `close()` は PGlite を閉じる
- 新規 `src/test/pglite.test.ts`
  - `createTestDb()` で作った DB に `nodes` を 1 行 insert し、select で読み戻せることを確かめる
  - neon-http の `getDb()` の戻り値を `AppDb` 型の変数に代入する、型だけの確認 (`const _check: AppDb = null as unknown as ReturnType<typeof getDb>;` のように、実行時に DB へ繋がない形)

## 触らない範囲
- `src/db/client.ts`、`src/db/schema.ts`、`src/db/auth-schema.ts`
- `drizzle/` のマイグレーション
- 既存のテスト

## 受け入れ条件
1. 検証コマンド 1 の出力が 3 行 (3 つのパッケージ名がそれぞれ 1 回ずつ出る)
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0 (AppDb への代入が型として通る)
4. 検証コマンド 4 が終了コード 0
5. 検証コマンド 5 が終了コード 0 (既存のテストも含めて通る)

## 検証コマンド
1. `node -e "const p=require('./package.json');for(const n of ['@modelcontextprotocol/sdk','@vercel/functions'])if(p.dependencies[n])console.log(n);if(p.devDependencies['@electric-sql/pglite'])console.log('@electric-sql/pglite')"`
2. `pnpm vitest run src/test/pglite.test.ts`
3. `pnpm typecheck`
4. `pnpm lint`
5. `pnpm test:unit`

## 補足
- vitest の設定は `src/**/*.test.ts` を拾う (`vitest.config.mts`)。`@/` のパス別名が使える
- マイグレーションのフォルダは `path.resolve(process.cwd(), "drizzle")` で解決してよい (テストはリポジトリのルートで実行される)
- `@modelcontextprotocol/sdk` は `node_modules` に既に見えることがあるが、`package.json` には無いので必ず `pnpm add` で正式に入れる。版は 1.32.1 に固定する (2.x は分割パッケージで、この設計とは合わない)
