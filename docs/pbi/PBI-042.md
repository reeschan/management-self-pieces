# PBI-042: MCP の口のテーブル (エージェント用トークン・IP 許可リスト・回数・監査ログ) とマイグレーション

- 担当モデル: agy claude-opus-5-5-high（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 0})
- 依存: なし

## 目的
MCP の口を守るための 4 つのテーブルを足す。エージェント用トークン (ハッシュだけを保存)、IP 許可リスト、トークンごとの回数の数え、監査ログ。マイグレーションは drizzle-kit で生成する。

## 対象
- 変更 `src/db/schema.ts`: 次の 4 テーブルと、それぞれの `$inferSelect` / `$inferInsert` の型 (既存の型の並びに合わせて末尾に) を足す
  - `agentTokens` (`agent_tokens`)
    - `id` text 主キー (アプリ側で `crypto.randomUUID()` を入れる)
    - `name` text not null
    - `tokenHash` (`token_hash`) text not null、一意インデックス `agent_tokens_token_hash_idx`
    - `scopes` jsonb `$type<string[]>()` not null default `[]`
    - `expiresAt` (`expires_at`) timestamptz null
    - `revokedAt` (`revoked_at`) timestamptz null
    - `lastUsedAt` (`last_used_at`) timestamptz null
    - `createdAt` (`created_at`) timestamptz not null defaultNow
  - `ipAllowlist` (`ip_allowlist`)
    - `id` serial 主キー
    - `cidr` text not null、一意インデックス `ip_allowlist_cidr_idx`
    - `label` text not null
    - `createdAt` timestamptz not null defaultNow
  - `mcpRateLimits` (`mcp_rate_limits`)
    - `tokenId` (`token_id`) text not null
    - `kind` text not null (`"all"` か `"write"`)
    - `windowStart` (`window_start`) timestamptz not null
    - `count` integer not null default 0
    - 主キーは (`token_id`, `kind`, `window_start`) の組
  - `mcpAuditLog` (`mcp_audit_log`)
    - `id` serial 主キー
    - `createdAt` timestamptz not null defaultNow、インデックス `mcp_audit_log_created_at_idx`
    - `mode` text not null (`"local"` か `"host"`)
    - `tokenId` text null、`ip` text null、`tool` text null、`argsSummary` (`args_summary`) text null
    - `outcome` text not null (`"ok"` / `"tool_error"` / `"rejected"`)
    - `reason` text null、`durationMs` (`duration_ms`) integer null
- 新規 `drizzle/0002_*.sql` と `drizzle/meta/0002_snapshot.json`、変更 `drizzle/meta/_journal.json`: `pnpm db:generate` で生成する (手で書かない)

## 触らない範囲
- `src/db/schema.ts` の既存のテーブルと型
- `src/db/auth-schema.ts`、`src/db/client.ts`
- `drizzle/0000_*.sql`、`drizzle/0001_*.sql` と、その snapshot
- `pnpm db:migrate` は実行しない (本番の DB に当てない)

## 受け入れ条件
1. 検証コマンド 1 の出力が `4` (4 テーブルの CREATE TABLE が新しいマイグレーションにある)
2. 検証コマンド 2 の出力が空 (新しいマイグレーションに DROP が無い)
3. 検証コマンド 3 の出力が `3` (マイグレーションが 3 件になっている)
4. 検証コマンド 4 が終了コード 0
5. 検証コマンド 5 が終了コード 0

## 検証コマンド
1. `cat drizzle/0002_*.sql | grep -cE 'CREATE TABLE "(agent_tokens|ip_allowlist|mcp_rate_limits|mcp_audit_log)"'`
2. `grep -n "DROP" drizzle/0002_*.sql`
3. `ls drizzle/*.sql | wc -l`
4. `pnpm typecheck`
5. `pnpm lint`

## 補足
- `pnpm db:generate` は `drizzle.config.ts` を読み、`.env.local` が無くても DB には接続しない (スキーマの差分だけで SQL を作る)
- 既存のテーブル定義の書き方 (`pgTable`、第 3 引数の配列でインデックスと主キー、`timestamp(..., { withTimezone: true })`) に合わせる
- ファイル冒頭のコメント「アプリの DB は … 作り直せる」に、1 行で「MCP の口の 4 テーブル (トークン・IP 許可リスト・回数・監査ログ) は作り直せない運用データ」と足してよい
- コメントは日本語。コミットはしない
