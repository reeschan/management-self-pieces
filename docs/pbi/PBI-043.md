# PBI-043: エージェント用トークンの発行・確認・失効

- 担当モデル: agy claude-opus-5-5-high（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 0, 'coupling': 1, 'ambiguity': 0})
- 依存: PBI-041, PBI-042

## 目的
MCP の口を呼ぶための鍵 (エージェント用トークン) を扱うモジュールを作る。値は発行したときに一度だけ返し、DB には SHA-256 のハッシュだけを残す。トークンには権限 (read・board・loop の部分集合)・期限・失効を持たせる。

## 対象
- 新規 `src/lib/mcp/tokens.ts`。すべて `AppDb` (`@/db/types`) を引数に取り、`getDb()` を直接呼ばない
  - `export const SCOPES = ["read", "board", "loop"] as const;` と `export type Scope = (typeof SCOPES)[number];`
  - `export function generateRawToken(): string`: `"msp_"` + 32 バイトのランダム値 (`crypto.randomBytes`) の base64url
  - `export function hashToken(raw: string): string`: SHA-256 の hex
  - `export async function issueToken(db, input: { name: string; scopes: Scope[]; expiresAt: Date | null; now: Date }): Promise<{ id: string; raw: string }>`
    - name は前後の空白を除いて 1〜60 文字、scopes は 1 つ以上で重複なし (違反は `Error` を投げる)
    - `id` は `crypto.randomUUID()`。DB に保存するのは `tokenHash` だけで、`raw` は戻り値でしか返さない
  - `export async function revokeToken(db, id: string, now: Date): Promise<boolean>`: 失効日時を入れる。存在しないか既に失効済みなら false
  - `export async function listTokens(db): Promise<Array<{ id; name; scopes; expiresAt; revokedAt; lastUsedAt; createdAt }>>`: 作成の新しい順。**ハッシュは返さない**
  - `export async function verifyToken(db, raw: string, now: Date): Promise<{ id: string; scopes: Scope[] } | null>`
    - `raw` が `"msp_"` で始まらない、または長さが 200 を超えるなら、DB を引かずに null
    - ハッシュで 1 行を引き、`crypto.timingSafeEqual` で保存済みのハッシュと比べる
    - 失効済み、または `expiresAt <= now` なら null
    - 通ったら `lastUsedAt = now` に更新して返す。scopes は `SCOPES` に含まれるものだけに絞る
- 新規 `src/lib/mcp/tokens.test.ts`: `createTestDb()` (`@/test/pglite`) を使う

## 触らない範囲
- `src/db/` (スキーマは PBI-042 で入っている)、`src/test/pglite.ts`
- 既存の `src/lib/` のモジュール

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。テストは少なくとも次を確かめる
   - 発行した `raw` で `verifyToken` すると id と scopes が返り、`lastUsedAt` が `now` になる
   - DB の行に `raw` そのものがどの列にも入っていない
   - 1 文字違う値・接頭辞が無い値・空文字は null
   - 失効後は null。期限ちょうど (`expiresAt == now`) は null
   - `listTokens` の戻り値にハッシュの項目が無い
   - 不正な name・空の scopes・知らない scope で `issueToken` が例外を投げる
2. 検証コマンド 2 の出力が空 (`getDb` を使っていない)
3. 検証コマンド 3 が終了コード 0
4. 検証コマンド 4 が終了コード 0

## 検証コマンド

## 補足
- `AppDb` は neon-http と PGlite の両方を受ける型。`db.batch` と `db.transaction` は使わない (片方に無いため)。1 文で済む insert / update / select で書く
- テーブルは `agentTokens` (`@/db/schema`)。列は `id, name, tokenHash, scopes, expiresAt, revokedAt, lastUsedAt, createdAt`
- `createTestDb()` はテストごと (`beforeEach`) に作り、`afterEach` で `close()` する
- 時刻は引数の `now` を使い、`new Date()` を中で呼ばない (テストで時計を固定するため)
- コメントは日本語。コミットはしない
