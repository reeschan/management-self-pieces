# PBI-045: 回数の上限と監査ログ

- 担当モデル: codex high（sonnet 相当） (select_model.py: 決定: sonnet。novelty・coupling・ambiguity のどれかが 1 以上（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 1, 'coupling': 1, 'ambiguity': 0})
- 依存: PBI-041, PBI-042

## 目的
ホストで動くとき、エージェント用トークンごとに 1 時間あたりの呼び出し回数に上限をかける (全体 1200 回、書き込み 300 回)。また、MCP の口への呼び出しと、弾いた呼び出しを監査ログに残し、90 日を過ぎた行を消せるようにする。

## 対象
- 新規 `src/lib/mcp/rate-limit.ts` (`AppDb` を引数に取る)
  - `export const RATE_LIMITS = { all: 1200, write: 300 } as const;`
  - `export function windowStartOf(now: Date): Date`: その時刻を含む 1 時間の窓の始まり (UTC の正時)
  - `export async function consumeRateLimit(db, input: { tokenId: string; kind: "all" | "write"; now: Date }): Promise<{ allowed: boolean; count: number }>`
    - `mcp_rate_limits` に (tokenId, kind, 窓の始まり) で 1 文の upsert (`insert ... onConflictDoUpdate` で `count = count + 1`、`returning`) をして、増やした後の count を得る
    - `count <= RATE_LIMITS[kind]` なら allowed
  - `export async function purgeRateLimits(db, now: Date): Promise<number>`: 窓の始まりが 2 時間より前の行を消し、消した件数を返す
- 新規 `src/lib/mcp/audit.ts` (`AppDb` を引数に取る)
  - `export type AuditEntry = { mode: "local" | "host"; tokenId: string | null; ip: string | null; tool: string | null; argsSummary: string | null; outcome: "ok" | "tool_error" | "rejected"; reason: string | null; durationMs: number | null; now: Date }`
  - `export async function recordAudit(db, entry: AuditEntry): Promise<void>`: `createdAt` には `entry.now` を入れる
  - `export async function listAudit(db, input: { onlyRejected: boolean; limit: number }): Promise<...>`: 新しい順。limit は 1〜500 に丸める
  - `export async function purgeAudit(db, now: Date): Promise<number>`: 90 日より前の行を消し、件数を返す
  - `export function summarizeArgs(args: unknown): string | null`
    - undefined / null なら null
    - オブジェクトなら、キーごとに: 文字列は 40 文字以下ならそのまま、それより長ければ先頭 20 文字 + `…(<全体の文字数>文字)`。数値・真偽値はそのまま。配列は `[<要素数>件]`。入れ子のオブジェクトは `{…}`
    - `JSON.stringify` した結果が 200 文字を超えたら 200 文字で切る
- 新規 `src/lib/mcp/rate-limit.test.ts` と `src/lib/mcp/audit.test.ts` (`createTestDb()` を使う)

   - 1200 回のループが遅ければ、`RATE_LIMITS` を差し替えられるようにはせず、そのまま回してよい (PGlite で数秒以内に収まる想定)。10 秒を超えるなら、件数を減らさずに `test` のタイムアウトを 30 秒にする

## 補足
- `AppDb` (`@/db/types`) は neon-http と PGlite の両方を受ける型。`db.batch` と `db.transaction` は使わない。数え上げは 1 文の upsert で原子的に行う (`sql\`${mcpRateLimits.count} + 1\``)
- テーブルは `mcpRateLimits` と `mcpAuditLog` (`@/db/schema`)
- 時刻は引数の `now` を使い、中で `new Date()` を呼ばない
- コメントは日本語。コミットはしない
