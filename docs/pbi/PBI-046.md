# PBI-046: MCP の口の入口の判定 (IP・トークン・回数・Host/Origin)

- 担当モデル: agy claude-opus-5-5-high（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 2, 'coupling': 2, 'ambiguity': 0})
- 依存: PBI-040, PBI-043, PBI-044, PBI-045

## 目的
MCP の口にリクエストが来たとき、ツールを動かす前に「通してよいか」を決める関数を作る。ホストでは IP 許可リスト → エージェント用トークン → 回数の上限の順に確かめる。ローカルではトークンと IP を見ず、Host と Origin だけを確かめる (ブラウザ経由で別のサイトから localhost を叩かれるのを防ぐため)。弾いたときは、理由を監査ログに残す。

## 対象
- 新規 `src/lib/mcp/gate.ts`
  - 型:
    ```ts
    export type GateContext = { db: AppDb; mode: "local" | "host"; clientIp: string | null; now: Date };
    export type GateResult =
      | { ok: true; tokenId: string | null; scopes: Scope[] }
      | { ok: false; response: Response };
    export async function gateRequest(req: Request, ctx: GateContext): Promise<GateResult>
    ```
  - **ホスト** (`mode === "host"`) の順番。弾いたら、その時点で止める
    1. `clientIp` が null、または `isIpAllowed(db, clientIp)` が false → 403、本文 `{"error":"forbidden"}`、監査ログの reason は `ip_not_allowed`
    2. `Authorization` ヘッダーが `Bearer <値>` の形でない、または `verifyToken(db, 値, now)` が null → 401、本文 `{"error":"unauthorized"}`、ヘッダー `WWW-Authenticate: Bearer`、reason は `invalid_token`
    3. `consumeRateLimit(db, { tokenId, kind: "all", now })` が not allowed → 429、本文 `{"error":"too many requests"}`、ヘッダー `Retry-After` (今の窓が終わるまでの秒数)、reason は `rate_limited`
    4. 通ったら `{ ok: true, tokenId, scopes: トークンの scopes }`
  - **ローカル** (`mode === "local"`)
    1. `Host` ヘッダーのホスト名 (ポートを除く。`[::1]:3000` の形も扱う) が `localhost` / `127.0.0.1` / `::1` のどれでもない → 403、reason は `bad_host`
    2. `Origin` ヘッダーがあり、そのホスト名が上の 3 つのどれでもない (または URL として読めない) → 403、reason は `bad_origin`
    3. 通ったら `{ ok: true, tokenId: null, scopes: ["read", "board", "loop"] }`
  - 弾いたときは `recordAudit` で `outcome: "rejected"`、`tool: null`、`argsSummary: null`、`durationMs: null`、`mode`、`ip: clientIp`、`tokenId: null` を残す
  - 403/401/429 の本文には、理由の区別を出さない (上の固定の本文だけ)
- 新規 `src/lib/mcp/gate.test.ts` (`createTestDb()` を使う)

## 触らない範囲

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。少なくとも次を確かめる
   - ホスト: 許可リストが空 → 403、許可リスト外の IP → 403、`clientIp` が null → 403
   - ホスト: 許可された IP でトークン無し / 不正 / 失効済み → 401 (`WWW-Authenticate` 付き)
   - ホスト: 許可された IP と正しいトークン → ok で、scopes がトークンのものと一致
   - ホスト: 回数の上限を超えたら 429 (`Retry-After` 付き)。テストでは、事前に `consumeRateLimit` を上限まで呼んで再現してよい
   - ホスト: 403/401/429 の本文が固定の本文と完全に一致する
   - ローカル: トークン無しで ok (scopes は 3 つ全部)、`Host: evil.example` → 403、`Origin: https://evil.example` → 403、`Origin: http://localhost:3000` → ok、`Host: [::1]:3000` → ok
   - 弾いたときに監査ログに `rejected` の行と reason が 1 行ずつ残る
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0

## 補足
- 使う関数: `verifyToken` (`./tokens`)、`isIpAllowed` (`./ip-allowlist`)、`consumeRateLimit` と `windowStartOf` (`./rate-limit`)、`recordAudit` (`./audit`)、`Scope` 型 (`./tokens`)、`AppDb` 型 (`@/db/types`)
- テストでは `new Request("https://app.example/api/mcp", { method: "POST", headers: {...} })` で作る。Host ヘッダーは `headers` に明示して渡す (Request は URL から Host を自動では入れない)
- テストの DB は `createTestDb()` (`@/test/pglite`)。トークンは `issueToken`、IP は `addAllowlistEntry` で用意する
- これは認証の要になる部分。判定の順番と、弾いたときに止まることを崩さない
