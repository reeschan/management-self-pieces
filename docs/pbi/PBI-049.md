# PBI-049: 設定画面の Server Actions (トークンの発行・失効、IP 許可リストの更新)

- 担当モデル: agy claude-opus-5-5-high（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 0, 'coupling': 0, 'ambiguity': 0})
- 依存: PBI-041, PBI-043, PBI-044

## 目的
設定画面から、エージェント用トークンの発行と失効、IP 許可リストの追加と削除、「今の IP を許可」を行えるようにする。どれも、ログインしていて、許可リスト (`ALLOWED_EMAILS`) に入っている人だけが実行できる。画面そのものは PBI-050 で作る。

## 対象
- 新規 `src/app/(app)/settings/actions.ts` (`"use server"`)。どの関数も最初に `getAllowedSession()` を確かめ、null なら `throw new Error("unauthorized")` (既存の `src/app/(app)/actions.ts` と同じ書き方)。最後に `revalidatePath("/settings")`
  - `issueAgentToken(input: { name: string; scopes: string[]; expiresInDays: number | null }): Promise<{ id: string; raw: string }>`
    - Zod で検証する: name は 1〜60 文字、scopes は `SCOPES` の値だけで 1 つ以上、expiresInDays は 1〜365 の整数か null
    - 期限は `now + expiresInDays 日`、null なら期限なし
    - `issueToken(getDb(), ...)` の戻り値をそのまま返す (`raw` はこの戻り値でしか画面に渡らない)
  - `revokeAgentToken(id: string): Promise<boolean>`: id は UUID の形だけを受け付ける
  - `addIpAllowlist(input: { cidr: string; label: string }): Promise<string>`: `addAllowlistEntry` を呼び、正規化後の cidr を返す。不正なら、`"CIDR の形が正しくない"` の Error を投げる
  - `removeIpAllowlist(id: number): Promise<boolean>`: 正の整数だけを受け付ける
  - `allowCurrentIp(label: string): Promise<string>`
    - 今の送信元 IP を `ipAddress` (`@vercel/functions`) で、`headers()` (`next/headers`) から取る
    - 取れない、またはループバック (`isLoopback`) なら `"今の IP を取得できない (ローカルで動いているときは IP 許可リストは使わない)"` の Error を投げる
    - `allowEntryFor(ip)` の範囲を、`addAllowlistEntry` で足して返す

## 触らない範囲
- `src/lib/mcp/` の各モジュール
- 既存の `src/app/(app)/actions.ts`、`src/app/(app)/layout.tsx`、`src/app/(app)/page.tsx`
- 画面 (PBI-050 で作る)

## 受け入れ条件
1. 検証コマンド 1 の出力が `5` (5 つの関数がすべて `getAllowedSession()` を確かめている)
2. 検証コマンド 2 の出力が `1` (ファイルの先頭が `"use server"`)
3. 検証コマンド 3 の出力が空 (`raw` やトークンの値を console に出していない)
4. 検証コマンド 4 が終了コード 0
5. 検証コマンド 5 が終了コード 0

## 検証コマンド
1. `grep -c "getAllowedSession()" "src/app/(app)/settings/actions.ts"`
2. `head -1 "src/app/(app)/settings/actions.ts" | grep -c '"use server"'`
3. `grep -n "console\." "src/app/(app)/settings/actions.ts"`
4. `pnpm typecheck`
5. `pnpm lint`

## 補足
- **この Next.js (16.4) は学習データと違う点がある。** 書く前に `node_modules/next/dist/docs/01-app/01-getting-started/07-mutating-data.md` を読むこと
- 使う関数: `issueToken`・`revokeToken`・`SCOPES` (`@/lib/mcp/tokens`)、`addAllowlistEntry`・`removeAllowlistEntry` (`@/lib/mcp/ip-allowlist`)、`allowEntryFor`・`isLoopback` (`@/lib/mcp/ip`)、`getDb` (`@/db/client`)、`getAllowedSession` (`@/lib/auth/server`)
- `ipAddress` の引数の型は、入った `@vercel/functions` の型定義で確かめる (`Request` か `{ headers }` を受ける)。`headers()` は Promise なので await する
- 時刻は `new Date()` でよい (Server Action は境界の外)
- コメントは日本語。コミットはしない
