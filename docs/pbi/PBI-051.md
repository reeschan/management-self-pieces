# PBI-051: README・SETUP・DESIGN に MCP の口の使い方を書く

- 担当モデル: opencode deepseek-v4.1-flash（haiku 相当） (select_model.py: 決定: haiku。どの条件にも当たらない（opencode の DeepSeek を先に試す）（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 0, 'coupling': 0, 'ambiguity': 0})
- 依存: PBI-048, PBI-050

## 目的
M1 で足した MCP の口を、持ち主が設定して使えるように、文書に手順と構成を書く。

## 対象
- 変更 `README.md`
  - 「主な機能」に 1 行足す: 「MCP の口: Claude Code から Node と看板を読む (`/api/mcp`)。エージェント用トークンと IP 許可リストで守る」
  - 「スクリプト」の表に `pnpm dev:local` の行を足す (「127.0.0.1 だけで待ち受けて開発サーバーを起動する (ローカル機能を使うとき)」)
- 変更 `docs/SETUP.md`: 末尾に「MCP の口」の節を足す
  - マイグレーションの適用 (`pnpm db:migrate`。4 つのテーブルが増える)
  - ホスト (Vercel) で使う手順
    1. 設定画面で「今の IP を許可」(または CIDR を追加)
    2. 設定画面でエージェント用トークンを発行し、値を環境変数 `PIECES_AGENT_TOKEN` に入れる (Windows は `setx PIECES_AGENT_TOKEN <値>`)
    3. `claude mcp add --scope user --transport http pieces https://<アプリ>/api/mcp --header "Authorization: Bearer ${PIECES_AGENT_TOKEN}"`
  - ローカルで使う手順: `.env.local` に `LOCAL_AGENT_FEATURES=1`、`pnpm dev:local` で起動、`http://127.0.0.1:3000/api/mcp` を登録 (トークン不要)
  - 守りの説明: 権限 (read / board / loop)、回数の上限 (全体 1200 回/時、書き込み 300 回/時)、監査ログ (90 日で削除)、IP 許可リストが空なら全部拒否
  - IP が変わって弾かれたときの戻し方 (設定画面の「今の IP を許可」、監査ログの「拒否だけ」で確かめる)
- 変更 `docs/DESIGN.md`
  - 「方針」に 1 行: 「MCP の口: 画面と同じデプロイで `/api/mcp` を出す。認証は ADR 0001」
  - 「ディレクトリ」に `api/mcp/route.ts`、`(app)/settings/`、`lib/mcp/`、`components/settings/`、`test/` を足す
  - 「テーブル」の表に 4 テーブル (`agent_tokens`・`ip_allowlist`・`mcp_rate_limits`・`mcp_audit_log`) を足す。これらは GitHub や Asana から作り直せない運用データである旨を 1 行で書く
  - 末尾に「関連」として `CONTEXT.md`、`docs/adr/`、`docs/specs/mcp-devloop-local.md` へのリンク
