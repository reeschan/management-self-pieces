# PBI-052: MCP の登録例で、トークンが設定ファイルに展開されないよう引用符を直す

- 担当モデル: agent opus（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 0, 'coupling': 0, 'ambiguity': 0}。route 先頭の agy は使用不可のため agent)
- 依存: PBI-050, PBI-051

## 目的
設定画面と docs/SETUP.md に載せた Claude Code への登録例が、`--header "Authorization: Bearer ${PIECES_AGENT_TOKEN}"` (二重引用符) や `$env:PIECES_AGENT_TOKEN` になっている。これだと、シェルが登録の時点でトークンの値を展開し、生の値が Claude Code の設定ファイル (`~/.claude.json`) に書き込まれる。仕様 (docs/specs/mcp-devloop-local.md のユーザーストーリー 24) は「設定ファイルにトークンをそのまま残さない」なので、シェルに展開させず、文字どおりの `${PIECES_AGENT_TOKEN}` を Claude Code に渡す形に直す。Claude Code は、接続するときに `headers` の `${VAR}` を環境変数から展開する。

## 対象
- 変更 `src/components/settings/token-section.tsx`
  - 画面に出す登録例を、ヘッダーを単一引用符で囲む形にする: `claude mcp add --scope user --transport http pieces <origin>/api/mcp --header 'Authorization: Bearer ${PIECES_AGENT_TOKEN}'`
  - 登録例のすぐ下に、1 行の注記を足す: 「ヘッダーは単一引用符のまま実行する (シェルにトークンを展開させず、Claude Code が接続するときに環境変数から読む)。登録後に `claude mcp get pieces` で `${PIECES_AGENT_TOKEN}` のまま保存されていることを確かめる」
- 変更 `docs/SETUP.md` の「9. MCP の口」の節
  - Bash の例: `export PIECES_AGENT_TOKEN=...` の行を消し、登録コマンドのヘッダーを単一引用符 `'Authorization: Bearer ${PIECES_AGENT_TOKEN}'` にする。トークンはシェルの設定ファイル (例 `~/.bashrc`) か `setx` で環境変数に入れておく、と文章で書く
  - PowerShell の例: `"Authorization: Bearer $env:PIECES_AGENT_TOKEN"` を `'Authorization: Bearer ${PIECES_AGENT_TOKEN}'` (単一引用符) にする
  - 例の後に、登録後の確認手順を足す: `claude mcp get pieces` を実行し、ヘッダーが `${PIECES_AGENT_TOKEN}` のまま (トークンの値が出ていない) ことを確かめる。値が出ていたら `claude mcp remove --scope user pieces` で外して登録し直す
- 変更 `docs/DESIGN.md` の「関連」の節: `CONTEXT.md` の説明「プロジェクトの背景」を「用語集」に直す

## 触らない範囲
- `token-section.tsx` の登録例と注記以外 (発行・失効・一度だけの表示の処理)
- docs/SETUP.md の「9. MCP の口」以外の節と、ローカルの登録例 (トークンを使わないので変えない)
- ほかのソースコード

## 受け入れ条件
1. 検証コマンド 1 の出力が空 (二重引用符で囲んだ Bearer のヘッダーが残っていない)
2. 検証コマンド 2 の出力が空 (`$env:PIECES_AGENT_TOKEN` が残っていない)
3. 検証コマンド 3 の出力が 2 以上 (SETUP.md に単一引用符のヘッダーが Bash と PowerShell の 2 か所以上ある)
4. 検証コマンド 4 の出力が 1 以上 (画面の登録例が単一引用符のヘッダーになっている)
5. 検証コマンド 5 の出力が 1 以上 (SETUP.md に `claude mcp get pieces` の確認手順がある)
6. 検証コマンド 6 が終了コード 0
7. 検証コマンド 7 が終了コード 0

## 検証コマンド
1. `grep -rn '"Authorization: Bearer \${PIECES' docs/SETUP.md src/components/settings/token-section.tsx` (オーケストレーターが修正: 元の形は範囲外の CRON_SECRET の curl の例にも当たっていた)
2. `grep -rn 'env:PIECES_AGENT_TOKEN' docs/SETUP.md src/components/settings/token-section.tsx`
3. `grep -cF -e "'Authorization: Bearer \${PIECES_AGENT_TOKEN}'" docs/SETUP.md`
4. `grep -cF -e "--header 'Authorization: Bearer" src/components/settings/token-section.tsx`
5. `grep -c "claude mcp get pieces" docs/SETUP.md`
6. `pnpm typecheck`
7. `pnpm lint`

## 補足
- `token-section.tsx` では登録例をテンプレートリテラルで組み立てている。`${PIECES_AGENT_TOKEN}` が JavaScript の埋め込みとして解釈されないよう、`\${PIECES_AGENT_TOKEN}` と書く (今の書き方と同じ)。変えるのは外側の二重引用符を単一引用符にすることだけ
- 文書の文体 (常体、簡潔) は既存に合わせる。トークンの値の例は `<トークン>` のような置き換え用の表記にし、本物らしい値を書かない
- コメントと文言は日本語。コミットはしない
