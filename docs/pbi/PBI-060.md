# PBI-060: devloop のテーブルとタスクの写しの列 (マイグレーション 0003)

- 担当モデル: agent opus（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 0, 'coupling': 0, 'ambiguity': 0}。route 先頭の agy は使用不可のため agent)
- 依存: なし

## 目的
devloop のアプリ側が使う 4 つのテーブルを足し、タスクの写し (`task_cache`) に列・タグ・meta を持たせる。形は復元した `R/db/schema.ts` をもとにし、仕様の改訂 (sprintLimit、最後に選ばれた時刻、1 日の上限の既定 1、sourceSha の null 許可) を入れる。

## 対象
- 変更 `src/db/schema.ts`
  - `taskCache` に列を足す: `section` text (null 可)、`tags` jsonb `$type<string[]>()` notNull default `[]`、`meta` jsonb `$type<Record<string, unknown>>()` (null 可)
  - `devProjects` (`dev_projects`) を足す。`R/db/schema.ts` の定義をもとに、次のとおりにする
    - `nodeId` text 主キー、`nodes.id` を参照 (onDelete cascade)
    - `enabled` boolean notNull default false
    - `paused` boolean notNull default true、`pauseReason` text (null 可)
    - `autonomy` integer notNull default 1 と CHECK `dev_projects_autonomy_check` (0〜3)
    - `maxIterationsPerDay` (`max_iterations_per_day`) integer notNull **default 1**
    - `maxPbisPerIteration` (`max_pbis_per_iteration`) integer notNull default 10
    - `sprintLimit` (`sprint_limit`) integer notNull default 6 (**新しい列**)
    - `lastSelectedAt` (`last_selected_at`) timestamptz (null 可) (**新しい列**)
    - `lastRunAt` (`last_run_at`) timestamptz (null 可)
    - `updatedAt` timestamptz notNull defaultNow
  - `devloopControl` (`devloop_control`): `R/db/schema.ts` のまま (key text 主キー、value text notNull、updatedAt)
  - `DevloopRunStatus` 型と `devloopRuns` (`devloop_runs`): `R/db/schema.ts` のまま (id, nodeId, iteration, phase, status, summary, tokens, startedAt, heartbeatAt, finishedAt と、インデックス `devloop_runs_node_id_started_at_idx`)
  - `iterations`: `R/db/schema.ts` をもとにし、**`sourceSha` は null を許す**
  - それぞれの `$inferSelect` / `$inferInsert` の型を、既存の型の並びの末尾に足す
  - drizzle-orm の import に、要るもの (`check`、`integer`、`sql` など) を足す
- 新規 `drizzle/0003_*.sql`、`drizzle/meta/0003_snapshot.json`、変更 `drizzle/meta/_journal.json`: `pnpm db:generate` で生成する (手で書かない)

## 触らない範囲
- 既存のテーブル (`taskCache` は列を足すだけ。既存の列・主キー・インデックスは変えない)
- `drizzle/0000`〜`0002` とその snapshot
- `pnpm db:migrate` は実行しない

## 受け入れ条件
1. 検証コマンド 1 の出力が `4`
2. 検証コマンド 2 の出力が空 (DROP が無い)
3. 検証コマンド 3 の出力が `3` 以上 (task_cache に 3 列を足す ALTER がある)
4. 検証コマンド 4 が終了コード 0 (PGlite で 0000〜0003 が適用でき、既存のテストも通る)
5. 検証コマンド 5 が終了コード 0
6. 検証コマンド 6 が終了コード 0

## 検証コマンド
1. `cat drizzle/0003_*.sql | grep -cE 'CREATE TABLE "(dev_projects|devloop_control|devloop_runs|iterations)"'`
2. `grep -n "DROP" drizzle/0003_*.sql`
3. `grep -cE 'ALTER TABLE "task_cache" ADD COLUMN' drizzle/0003_*.sql`
4. `pnpm test:unit`
5. `pnpm typecheck`
6. `pnpm lint`

## 補足
- `pnpm db:generate` は DB に接続しない
- `sourceSha` の null 許可は、`report_run` からはこの値が届かないため
