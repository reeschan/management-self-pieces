# PBI-062: テスト用の偽の Tracker (メモリ上の Asana)

- 担当モデル: codex high（sonnet 相当） (select_model.py: 決定: sonnet。novelty・coupling・ambiguity のどれかが 1 以上（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 0})
- 依存: PBI-061

## 目的
看板・制御・MCP のツールのテストで、Asana の代わりに使うメモリ上の Tracker を作る。テストの境界 (seam) を「本物の Drizzle + 偽の Tracker」にするための部品。

## 対象
- 新規 `src/test/fake-tracker.ts`
  - `export function createFakeTracker(options?: { now?: () => Date }): FakeTracker`
  - `FakeTracker = TrackerProvider & { state: FakeTrackerState }`。`state` はテストから直接読み書きできるメモリ上のデータ
    - projects (gid → { name, notes })、sections (projectId → TrackerSection[])、tasks (gid → { projectId, name, notes, completed, dueOn, sectionId, assigneeId, tags: string[] })、tags (name → gid)、comments (taskId → TrackerComment[])
    - gid は `"fake-<連番>"` で振る
  - `TrackerProvider` の全メソッドを、上のデータに対して素直に実装する
    - `createTask` で `sectionId` があればそのセクションに入れる
    - `listTaskDetails` と `getTask` は `sectionName` も埋める
    - `addComment` は `authorId: null` で足す。テストで持ち主のコメントを作れるよう、`state` に直接足せるヘルパー `addCommentAs(taskId, text, authorId)` も出す
    - `createWebhook` は何もしないで `{ webhookId: "fake-webhook" }` を返す
    - 存在しない gid を渡されたら `Error("not found")` を投げる
- 新規 `src/test/fake-tracker.test.ts`: セクションの作成と一覧、タスクの作成→移動→更新→`getTask`、タグ、コメントの一覧 (作成者付き) を確かめる
