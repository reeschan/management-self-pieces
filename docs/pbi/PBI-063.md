# PBI-063: 項目の meta (notes に埋め込む YAML) と種類・出どころ

- 担当モデル: codex high（sonnet 相当） (select_model.py: 決定: sonnet。novelty・coupling・ambiguity のどれかが 1 以上（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 0})
- 依存: なし

## 目的
看板の項目の meta は、Asana のタスクの notes の末尾に `<!-- devloop ... -->` で YAML として埋め込む (ADR 0002)。その読み書きと、項目の種類・出どころ・ID の連番を扱う純粋な関数を戻す。

## 対象
- 新規 `src/lib/devloop/item-meta.ts`: `R/lib/devloop/item-meta.ts` を土台にする。export は R と同じにする
  - `ItemMetaSchema`、`ItemMeta`、`ITEM_TYPES` (story / bug / debt / experiment / chore)、`ITEM_ORIGINS` (pm / biz / tl / owner)、`typeTag`、`originTag` (`from:<origin>`)、`parseItemNotes(notes)` (`{ body, meta, error }`)、`buildItemNotes(body, meta)`、`nextItemId(type, existingIds)`
  - 振る舞いは R のまま: いちばん最後の印を読む。閉じていない・壊れている・スキーマ違反のときは meta を null にし、error に理由を入れる。build は既存の印をすべて外し、文字列の中の `-->` を `-- >` にする
- 新規 `src/lib/devloop/item-meta.test.ts`

## 触らない範囲
- ほかのファイル

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。少なくとも次を確かめる
   - build → parse で同じ meta と本文が戻る
   - 印が無い → meta null・error null。閉じていない・YAML が壊れている・スキーマ違反 → meta null・error あり
   - 印が 2 つあれば最後のものを読む。build は既存の印を外して 1 つにする
   - hypothesis に `-->` を含む値でも、印が途中で閉じない
   - `nextItemId` が種類ごとの接頭辞で次の番号を振り、9999 を超えると例外
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0
