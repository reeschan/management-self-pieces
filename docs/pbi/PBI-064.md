# PBI-064: タスクの写しに列・タグ・meta を保存し、項目の持ち主の Node を引く

- 担当モデル: codex high（sonnet 相当） (select_model.py: 決定: sonnet。novelty・coupling・ambiguity のどれかが 1 以上（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 1, 'coupling': 1, 'ambiguity': 0})
- 依存: PBI-060, PBI-061, PBI-062, PBI-063

## 目的
看板の画面とツールは、Asana のタスクの写し (`task_cache`) を読む。写しに列 (セクション名)・タグ・meta を保存し、Webhook で読み直しても消えないようにする。あわせて、「ある項目 (タスク) がどの Node の看板のものか」を写しから引く関数を作る。ツールが、Node に紐づかないタスクに触れないようにするため。

## 対象
- 新規 `src/lib/devloop/task-cache.ts` (`AppDb` を引数に取る)
  - `saveTaskCache(db, input: { nodeId: string; projectId: string; details: TrackerTaskDetail[]; now: Date }): Promise<number>`
    - その Node のプロジェクト (provider `"asana"`、`projectExternalId = projectId`) の行を消してから、`details` を insert する (2 文。batch は使わない)
    - 各行に `section` (= `sectionName`)、`tags`、`meta` (= `parseItemNotes(notes).meta`。null 可) を入れる
    - insert した件数を返す
  - `findCachedItem(db, itemId: string): Promise<{ nodeId: string; projectExternalId: string; section: string | null } | null>`
  - `countOwnerDecisions(db, nodeId?: string): Promise<number>`: 列が「Owner 判断」で未完了の行の件数 (nodeId を省けば全 Node)
- 変更 `src/lib/tracker/service.ts` の `refreshTasks`
  - `getTracker().listTasks` の代わりに `listTaskDetails` を使い、`saveTaskCache(getDb(), ...)` で保存する (列・タグ・meta が既定値に戻らないようにする)
  - 戻り値 (件数) と、リンクが無いときに 0 を返す振る舞いは変えない
- 新規 `src/lib/devloop/task-cache.test.ts` (`createTestDb()` を使う。`nodes` と `external_refs` に行を用意する)

## 触らない範囲
- `service.ts` の `refreshTasks` 以外の関数
- `src/db/`、`src/lib/tracker/asana.ts`・`types.ts`
