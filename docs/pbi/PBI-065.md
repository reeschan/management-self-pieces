# PBI-065: 看板のサービス (列の用意・読み取り・起票・移動・更新・コメント・Owner 判断)

- 担当モデル: agent opus（opus 相当） (select_model.py: 決定: opus。coupling=2; scores {'novelty': 1, 'coupling': 2, 'ambiguity': 1}。route 先頭の agy は使用不可のため agent)
- 依存: PBI-064

## 目的
devloop の看板を扱うサービスを戻す。復元した `R/lib/devloop/board.ts` を土台にし、`AppDb` と偽の Tracker でテストできる形にする。ツール (PBI-068) と画面 (PBI-071〜074) がこのサービスを使う。

## 対象
- 新規 `src/lib/devloop/board.ts`
  - R と同じ export: `SECTIONS` (Inbox, Backlog, Sprint, In Progress, Biz Review, Done, Owner 判断, Rejected)、`Section`、`isSection`、`LIMITS = { inbox: 15, bizProposalsPerIteration: 3 }`、`DEFAULT_SPRINT_LIMIT = 6`、`BoardLimitCode`、`BoardLimitError`
  - `BoardError(code: "not_linked" | "not_found" | "node_mismatch", message)` を足す
  - `createBoardService(deps: { db: AppDb; tracker: TrackerProvider; ownerAssigneeId?: string; now?: () => Date })`。Asana のプロジェクトは `external_refs` (provider `"asana"`) から引き、無ければ `BoardError("not_linked")`
  - メソッド (R をもとに、次の点を変える)
    - `ensureSections(nodeId)`: 足りないセクションを作る。引数は R と違い nodeId
    - `getBoard(nodeId, opts?: { sections?: Section[] })`
      - Asana から読み (`listTaskDetails`)、写しを `saveTaskCache` で保存し、列ごとにまとめて返す (`sections` があればその列だけ)
      - 項目 (`BoardItem`) は R の形に `ownerComments: { text: string; createdAt: string }[]` を足す
      - Owner のコメントは、**「Owner 判断」の列の項目だけ** `listComments` で読む (API の呼び出しを増やしすぎないため)。他の列は空配列
      - Owner のコメントとみなすのは、`authorId === ownerAssigneeId`、または本文が `[from:owner]` で始まるもの
    - `createItem(nodeId, input)`: R の上限 (`inbox_full`・`biz_proposal_limit`・`sprint_full`) と ID の連番、タグ付けをそのまま。作った後に写しを読み直す
    - `moveItem(nodeId, itemId, section, { sprintLimit })`: `resolveItemNode` で確かめてから動かす。Sprint の上限は R のとおり (その項目自身は数えない)。Done にしても完了にしない
    - `updateItem(itemId, { nodeId?, name?, body?, meta? })`: meta は **丸ごと置き換える** (R は重ねていた)。今の内容は `getTask` で読む
    - `commentItem(itemId, text, { nodeId? })`
    - `requestOwner(nodeId, { title, reason, itemId? })`: R のとおり (担当は ownerAssigneeId、元の項目は notes で紐づけ、Owner 判断へ移してコメント)
    - `answerOwner(nodeId, itemId, text)`: 本文の先頭に `[from:owner] ` を付けてコメントする (画面の受け箱が使う)
    - `resolveItemNode(itemId, nodeId?)`: `findCachedItem` で項目の Node を引く。写しに無ければ、nodeId が渡されていればその Node の写しを読み直してもう一度引く。それでも無ければ `BoardError("not_found")`。nodeId と違えば `BoardError("node_mismatch")`
    - 書き込みのメソッドは、終わった後にその Node の写しを読み直す
- 新規 `src/lib/devloop/board.test.ts` (`createTestDb()` と `createFakeTracker()`)

## 触らない範囲
- `task-cache.ts`・`item-meta.ts` (使うだけ)、`src/lib/tracker/`、`src/lib/mcp/`
