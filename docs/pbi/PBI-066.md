# PBI-066: devloop の制御サービス (設定・停止・次の Node・実行の記録)

- 担当モデル: agent opus（opus 相当） (select_model.py: 決定: opus。coupling=2; scores {'novelty': 1, 'coupling': 2, 'ambiguity': 0}。route 先頭の agy は使用不可のため agent)
- 依存: PBI-060

## 目的
どの Node をいつ回すか、止まっているか、実行をどう記録するかを決めるサービスを戻す。復元した `R/lib/devloop/control.ts` を土台にし、仕様の改訂 (全体の 1 日の上限、sprintLimit、最後に選ばれた時刻、無効も停止扱い) を入れる。

## 対象
- 新規 `src/lib/devloop/control.ts`: R を土台にし、`AppDb` を受け取る形にする
  - 純粋な関数は R のまま残す: `tokyoDateKey`、`tokyoDayStart`、`resolveStop`、`pickNextProject`、`shouldAutoPause`、`parseGlobalStop`。次の点を変える
    - 設定 (`ControlSettings`) に `sprintLimit` (1〜20、既定 6) を足す。`maxIterationsPerDay` の既定は 1。`SettingsPatchSchema` も合わせる
    - `pickNextProject(candidates, runsToday, now, globalStop, globalDailyLimit)`
      - 全体の今日の件数 (全 Node の合計) が `globalDailyLimit` 以上なら null
      - 候補は、止まっていない (`resolveStop` で停止でない) かつ、その Node の今日の件数が `maxIterationsPerDay` 未満のもの
      - 並びは、進行中のイテレーションがあるものを先に、次に「最後に選ばれた時刻 (無ければ最後の実行の時刻)」が古い順 (どちらも無いものが最初)、同じなら nodeId 順
    - `parseDailyLimit(value: string | undefined): number`: 行が無ければ 1、読めなければ 0 (止める側に倒す)、1〜20 に丸める
  - `createControlService({ db, now? })` のメソッド (R をもとに)
    - `getSettings(nodeId)`、`updateSettings(nodeId, patch)`、`setGlobalStop(on, reason?)`、`getGlobalStop()`、`setDailyLimit(n)`、`getDailyLimit()`
    - `isStopped(nodeId)`: 全体停止・無効・一時停止のどれかで true
    - `pause(nodeId, reason)`、`resume(nodeId)`
    - `nextProject()`: 選んだ Node の `lastSelectedAt` を now にして返す。返す形は `{ nodeId, sourceRepo, autonomy, maxPbisPerIteration, sprintLimit, openIteration }`
    - `startRun`・`heartbeat`・`finishRun`・`staleRuns`: R のまま (finishRun は lastRunAt を更新し、直近 3 件がすべて failed なら一時停止)
    - `listRuns(nodeId, limit)`: 新しい順 (画面用)
  - `devloop_control` の key は `global_stop` (R のまま) と `daily_limit` (新しい)
- 新規 `src/lib/devloop/control.test.ts`: 純粋な関数のテストと、`createTestDb()` を使うサービスのテスト

## 触らない範囲
- `src/db/`、`src/lib/devloop/board.ts` ほかの devloop のファイル

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。少なくとも次を確かめる
   - 全体の 1 日の上限 (既定 1) に達すると `nextProject` が null。Node ごとの上限でも外れる
   - 進行中のイテレーションの Node が先、次に最後に選ばれた時刻の古い順。選ぶと `lastSelectedAt` が更新され、続けて呼ぶと別の Node が選ばれる
   - 全体停止・無効・一時停止で `isStopped` が true。`global_stop` が読めない値なら停止扱い。`daily_limit` が読めない値なら 0 (= 回さない)
   - 3 回続けて failed で自動で一時停止し、理由が入る
   - 今日の件数は、release で succeeded の実行を Asia/Tokyo の日付で数える (日付の境目のケースを含む)
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0

## 補足
- 共有メモリに残っていた以前の実装メモ: `global_stop` の value は JSON `{"on":bool,"reason":string|null}`。読めない値は安全側で停止扱い。finishRun の lastRunAt 更新は update のみ。pause/resume/updateSettings は既定値で upsert
