# PBI-067: イテレーションの記録 (IterationManifest) の検証と保存

- 担当モデル: codex high（sonnet 相当） (select_model.py: 決定: sonnet。novelty・coupling・ambiguity のどれかが 1 以上（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 0})
- 依存: PBI-060

## 目的
devloop の PC 側は、イテレーションの状態を `docs/iterations/NNN/iteration.yaml` に持つ。`report_run` でその中身 (`iteration_manifest`) が届いたら、検証して `iterations` テーブルに保存する。形は devloop リポジトリの雛形 `C:\Users\owner\Documents\dev\myapp\devloop\skills\devloop\templates\iteration\iteration.yaml` と同じ。

## 対象
- 新規 `src/lib/devloop/iteration-manifest.ts`
  - `IterationManifestSchema` (Zod。知らないキーは捨てる)
    - `number`: 1 以上の整数
    - `goal`: 1〜300 文字
    - `phase`: plan | build | verify | review | retro | groom | release | done | owner_wait
    - `stories`: 最大 50 件。各 `{ id: /^[SBDEC]-\d{4}$/, title: 1〜200 文字, status: planned | done | carried_over | owner | rejected, biz?: accepted | changes_requested }`
    - `biz_scores`: `{ value?, usability?, coherence? }` (各 1〜5 の整数)。既定 `{}`
    - `started_at`: ISO 日時の文字列 (必須)
    - 任意: `result` (accepted | partially_accepted | rejected | aborted)、`finished_at` (ISO 日時)、`pr_url` (https の URL)、`stats` (オブジェクト。JSON にして 10,000 文字まで)
  - `export type IterationManifest`
  - `upsertIteration(db: AppDb, nodeId: string, manifest: IterationManifest): Promise<void>`: (nodeId, number) で upsert する。列への対応は `goal`・`phase`・`stories`・`bizScores`・`result`・`prUrl`・`stats`・`startedAt`・`finishedAt`。`sourceSha` は触らない (null のまま)
  - `listIterations(db, nodeId): Promise<IterationRow[]>`: 番号の新しい順
- 新規 `src/lib/devloop/iteration-manifest.test.ts` (`createTestDb()`)

## 触らない範囲
- `src/db/`、devloop リポジトリ (読むだけ)

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。少なくとも次を確かめる
   - 雛形と同じ形の正しい値が通り、知らないキー (`rework_count` など) が捨てられる
   - goal が空・300 文字超、phase が不正、story の id の形違い、stats が大きすぎる、pr_url が https でない → 失敗
   - `upsertIteration` で 1 行でき、同じ番号でもう一度呼ぶと更新される。別の Node の同じ番号は別の行
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0
