# PBI-069: MCP の口に制御のツールを足す (loop 権限・is_stopped) と、get_project の devloop の情報

- 担当モデル: agent opus（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 1, 'coupling': 1, 'ambiguity': 0}。route 先頭の agy は使用不可のため agent)
- 依存: PBI-068

## 目的
devloop のランナーが tick ごとに呼ぶ制御のツール (`next_project`・`report_run`・`pause`・`is_stopped`) を足し、`get_project` に devloop の設定と状態を載せる。

## 対象
- 変更 `src/lib/mcp/devloop-tools.ts`: `registerLoopTools(server, ctx)` を足す
  - `next_project` (loop, write): 入力なし。`control.nextProject()` の結果 (null 可) を返す
  - `report_run` (loop, write): 入力 `{ node_id, run_id? (1〜100), phase (1〜40), summary (0〜2,000), status?: "running" | "succeeded" | "failed" | "noop" | "rate_limited", iteration? (0 以上の整数), tokens? (オブジェクト。JSON で 2,000 文字まで), iteration_manifest? }`
    - status が無ければ `startRun` (run_id を省いたら `randomUUID()` を振る)、`running` は `heartbeat`、ほかは `finishRun`。返す値に run_id を含める
    - `iteration_manifest` があれば `IterationManifestSchema` で検証して `upsertIteration` する。不正なら `ToolError("invalid_manifest", ...)` (中身の詳細は返さない)
    - 復元した `R/lib/devloop/mcp-tools.ts` の `report_run` が元の形
  - `pause` (loop, write): 入力 `{ node_id, reason (1〜500) }`
  - `is_stopped` (**read**, write: false): 入力 `{ node_id }`。`{ stopped: boolean }` を返す
  - 4 つとも `requireNode` で Node の存在を確かめる (next_project を除く)
- 変更 `src/lib/mcp/tools.ts`
  - `get_project` の `devloop: null` を、`{ settings, stopped, pauseReason, lastRunAt, sectionCounts, openOwnerDecisions }` に置き換える
    - `settings` は `control.getSettings`、`sectionCounts` は写し (`task_cache`) の列ごとの未完了の件数、`openOwnerDecisions` は `countOwnerDecisions(db, nodeId)`
    - Asana につながっていない Node でも例外にせず、件数は 0 にする
  - `registerTools` の最後で `registerLoopTools` も呼ぶ
- 新規 `src/lib/mcp/loop-tools.test.ts`: `handleMcpRequest` に JSON-RPC を送る形 (`createTestDb()`、`createFakeTracker()`)
- 変更 `src/lib/mcp/handler.test.ts`: `get_project` の期待値を新しい形に合わせて直すだけ

## 触らない範囲
- `gate.ts` ほか M1 の認証まわり、`src/lib/devloop/` のサービス (使うだけ)
- `registerBoardTools` の中身

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。少なくとも次を確かめる
   - board だけのトークンで `next_project` を呼ぶと `forbidden:`。read のトークンで `is_stopped` が呼べる
   - `next_project` が Node を返し、全体の上限に達すると null
   - `report_run`: 開始 → ハートビート → 終了で `devloop_runs` の行が変わる。run_id を省いた開始で run_id が振られる。3 回続けて failed で Node が一時停止になる
   - `report_run` の `iteration_manifest` が正しければ `iterations` に入り、不正なら `invalid_manifest:` で行は増えない
   - `pause` の後に `is_stopped` が true。全体停止でも true
   - `get_project` に devloop の設定・停止・件数が入る
2. 検証コマンド 2 が終了コード 0
3. 検証コマンド 3 が終了コード 0
4. 検証コマンド 4 が終了コード 0
