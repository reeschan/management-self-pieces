# PBI-070: devloop の画面向けの読み取り (Node ごとの表示データと API)

- 担当モデル: agent opus（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 0}。route 先頭の agy は使用不可のため agent)
- 依存: PBI-065, PBI-066, PBI-067

## 目的
Node のパネルの「看板」「開発ループ」「イテレーション」タブが表示するデータを、1 つの API でまとめて返す。パネルは今も `GET /api/nodes/<id>` を fetch しているので、同じ流儀で `GET /api/nodes/<id>/devloop` を足す。

## 対象
- 新規 `src/lib/devloop/view.ts`
  - `loadDevloopView(db: AppDb, nodeId: string, deps: { control: ControlService }): Promise<DevloopView | null>` (Node が無ければ null)
  - `DevloopView = { linked: boolean; asanaUrl: string | null; columns: { section: string; items: { id; name; tags; meta; metaError; url; completed }[] }[]; settings; stopped: boolean; pauseReason: string | null; globalStop: { on: boolean; reason: string | null }; runs: RunRow[] (新しい順に 20 件); iterations: IterationRow[] }`
  - 看板は Asana を呼ばずに **写し (`task_cache`) から** 組み立てる (画面を速くするため)。列の並びは `SECTIONS` の順。写しに列が無い行は「未分類」としてまとめる
- 新規 `src/app/api/nodes/[id]/devloop/route.ts`
  - `GET` だけ。最初に `getAllowedSession()`、null なら 401
  - `loadDevloopView(getDb(), id, { control: createControlService({ db: getDb() }) })`。null なら 404
  - 想定外の例外は `console.error` に出して 500 (`{"error":"internal error"}`)
  - 既存の `src/app/api/nodes/[id]/route.ts` の書き方に合わせる
- 新規 `src/lib/devloop/view.test.ts` (`createTestDb()`)

## 触らない範囲
- 既存の `src/app/api/nodes/[id]/route.ts` と `asset/route.ts`
- `src/lib/devloop/` の他のファイル (使うだけ)

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。少なくとも次を確かめる: 存在しない Node で null、Asana につながっていない Node で `linked: false` と空の列、写しの行が列ごと・`SECTIONS` の順にまとまる、実行は新しい順に 20 件まで、イテレーションが入る、停止の状態が入る
2. 検証コマンド 2 の出力が `1` (ルートが `getAllowedSession()` を確かめている)
3. 検証コマンド 3 が終了コード 0
4. 検証コマンド 4 が終了コード 0
5. 検証コマンド 5 が終了コード 0

## 検証コマンド
1. `pnpm vitest run src/lib/devloop/view.test.ts`
2. `grep -c "getAllowedSession()" "src/app/api/nodes/[id]/devloop/route.ts"`
3. `pnpm typecheck`
4. `pnpm lint`
5. `pnpm build`
