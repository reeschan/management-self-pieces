# PBI-073: Owner 判断の受け箱と、ヘッダーの件数のバッジ

- 担当モデル: codex high（sonnet 相当） (select_model.py: 決定: sonnet。novelty・coupling・ambiguity のどれかが 1 以上（2026-10-23 までは codex を agy より先に試す）; scores {'novelty': 1, 'coupling': 0, 'ambiguity': 0})
- 依存: PBI-064, PBI-071

## 目的
devloop が持ち主に判断を求めた項目 (「Owner 判断」の列) を、全 Node 分まとめて 1 つの画面で見て、その場で答えられるようにする。答えると Asana にコメント (`[from:owner]` 付き) が付き、次の tick で devloop が続きから進む。未回答の件数はヘッダーに出す。

## 対象
- 新規 `src/lib/devloop/owner-inbox.ts`: `listOwnerDecisions(db: AppDb): Promise<{ nodeId; nodeTitle; itemId; name; url; meta }[]>`。写し (`task_cache`) から、列が「Owner 判断」で未完了の行を、Node の名前付きで返す (Node の名前順、次に項目の名前順)
- 新規 `src/lib/devloop/owner-inbox.test.ts` (`createTestDb()`)
- 新規 `src/app/(app)/owner/page.tsx` (サーバーコンポーネント)
  - `await connection()` してから読む
  - 見出し「Owner 判断」と件数。0 件なら「答えを待っている判断はありません」
  - 項目ごとに、Node の名前・項目の名前・Asana へのリンク・回答欄 (`OwnerAnswerForm`)
- 新規 `src/components/owner/owner-answer-form.tsx` (`"use client"`): 本文を入力して `answerOwnerDecision(nodeId, itemId, text)` を呼ぶ。送ったら「送りました」と出して欄を空にする。エラーの message を出す
- 変更 `src/app/(app)/layout.tsx`: ヘッダーのナビに「Owner 判断」(`/owner`) のリンクを足し、未回答が 1 件以上なら件数のバッジを付ける (`countOwnerDecisions(getDb())`)。件数の取得に失敗してもヘッダーは出す (バッジだけ出さない)

## 触らない範囲
- layout のセッションと許可リストの確認、既存のリンク
- `src/lib/devloop/` の他のファイル (使うだけ)

## 受け入れ条件
1. 検証コマンド 1 が終了コード 0。少なくとも次を確かめる: 「Owner 判断」で未完了の行だけが返る、完了済みと他の列は返らない、Node の名前が付く、並び順
2. 検証コマンド 2 の出力が `1` 以上 (layout に /owner へのリンクがある)
3. 検証コマンド 3 が終了コード 0
4. 検証コマンド 4 が終了コード 0
5. 検証コマンド 5 が終了コード 0
