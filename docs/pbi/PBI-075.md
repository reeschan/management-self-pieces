# PBI-075: devloop リポジトリの追記 (イテレーションの記録を送る、トークンを展開しない登録)

- 担当モデル: agent opus（opus 相当） (select_model.py: 決定: opus。sensitive; scores {'novelty': 0, 'coupling': 0, 'ambiguity': 0}。route 先頭の agy は使用不可のため agent)
- 依存: PBI-069

## 目的
アプリ側の `report_run` が `iteration_manifest` を受け取れるようになったので、devloop の PC 側のスキルがそれを送るようにする。あわせて、MCP の登録スクリプトがトークンを設定ファイルに展開しないよう直す。**これは別のリポジトリ (`C:\Users\owner\Documents\dev\myapp\devloop`、まだコミットが無い) の変更**。

## 対象 (すべて `C:\Users\owner\Documents\dev\myapp\devloop` の中)
- 変更 `skills/devloop/SKILL.md` の「tick の手順」
  - 6 (フェーズを進めてコミットする) の後、または 7 (終わり方) の `report_run` の説明に、次を足す: 「フェーズを進めたとき (advance した後) は、`<wt>` の `docs/iterations/NNN/iteration.yaml` を読み、その中身をオブジェクトにして `report_run` の `iteration_manifest` に付けて送る。アプリは知らないキーを捨てる。送れなかった (`invalid_manifest`) ときは summary にその旨を書き、tick は失敗にしない」
  - 既存の手順の番号と文言は変えず、足すだけにする
- 変更 `scripts/install.ps1`: MCP を登録する行 (`claude mcp add ... --header "Authorization: Bearer ${env:PIECES_AGENT_TOKEN}"`) を、ヘッダーの値を文字どおり `Authorization: Bearer ${PIECES_AGENT_TOKEN}` にして渡す形に直す (PowerShell の単一引用符を使う。シェルにトークンを展開させない)。`PIECES_AGENT_TOKEN` が無いときに止まる既存のチェックはそのまま残す。登録の後に `claude mcp get pieces` の結果にトークンの値が出ていないかを確かめる案内を 1 行出す
- 変更 `README.md` (devloop リポジトリ) の「MCP の登録」: 上の変更に合わせて、トークンは環境変数に置いたまま、設定ファイルには `${PIECES_AGENT_TOKEN}` として保存されることを 1〜2 行で書く

## 触らない範囲
- devloop リポジトリの他のファイル (phases・agents・scripts の他のもの)
- management-self-pieces のファイル
- `install.ps1` を**実行しない** (`~/.claude` と MCP の登録を変えてしまうため)
- git の操作 (devloop リポジトリにはまだコミットが無い。add も commit もしない)

## 受け入れ条件
1. 検証コマンド 1 の出力が `1` 以上 (SKILL.md に iteration_manifest の説明がある)
2. 検証コマンド 2 の出力が空 (install.ps1 に `${env:PIECES_AGENT_TOKEN}` を展開する形が残っていない)
3. 検証コマンド 3 の出力が `1` 以上 (install.ps1 が文字どおりの `${PIECES_AGENT_TOKEN}` を渡す)
4. 検証コマンド 4 が終了コード 0 (PowerShell として構文が正しい)

## 検証コマンド
1. `grep -c "iteration_manifest" /c/Users/owner/Documents/dev/myapp/devloop/skills/devloop/SKILL.md`
2. `grep -n 'env:PIECES_AGENT_TOKEN}' /c/Users/owner/Documents/dev/myapp/devloop/scripts/install.ps1 | grep -v 'Test-Path\|IsNullOrEmpty\|-not'`
3. `grep -cF '${PIECES_AGENT_TOKEN}' /c/Users/owner/Documents/dev/myapp/devloop/scripts/install.ps1`
4. `powershell -NoProfile -Command "$errs = $null; $null = [System.Management.Automation.Language.Parser]::ParseFile('C:\Users\owner\Documents\dev\myapp\devloop\scripts\install.ps1', [ref]$null, [ref]$errs); if ($errs.Count) { $errs; exit 1 }"`

## 補足
- (オーケストレーターが修正) 検証コマンド 4 は、PowerShell 5.1 では未定義の変数に [ref] を付けられないため、先頭に `$errs = $null;` を足した。検証コマンド 3 は、rtk のフックの下では結果が狂うことがあるので `/usr/bin/grep` で実行する
- 検証コマンド 2 は、トークンの有無を確かめる行 (`$env:PIECES_AGENT_TOKEN` を読むだけの行) を除外している。除外の条件が実際の行と合わなければ、報告にそのまま書く
