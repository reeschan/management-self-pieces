# PBI-082: nodes のスキーマを変え、マイグレーションを作る

- 担当モデル: agent sonnet high（sonnet 相当、review deep）
- 依存: PBI-080, PBI-081

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
Node をアプリで持つため、nodes にリポジトリ id・届くか・作成日時を足し、リポジトリの名前と詳細のパスを NULL 可にし、`source_sha` と `import_errors` を消す。型が変わって落ちる箇所を直し、devloop が届かない Node を選ばないようにする。

## 対象
- 変更 `src/db/schema.ts` (`nodes` は `docs/pbi/_node_common.md` の「DB」の列のとおり):
  - 追加 `repoId` (`bigint("repo_id", { mode: "number" })`、NULL 可、一意)、`repoReachable` (`boolean("repo_reachable")`、NOT NULL、既定 true)、`createdAt` (`timestamp with time zone`、NOT NULL、既定 now)
  - `sourceRepo` と `detailPath` を NULL 可にし、`sourceRepo` に一意制約を付ける
  - 消す: `sourceSha` 列、`importErrors` テーブルと `ImportErrorRow`・`NewImportErrorRow` 型 (`iterations.sourceSha` は別物なので残す)
- 新規 マイグレーション: **2 回に分けて生成する** (drizzle-kit は同じテーブルで列の追加と削除が同時にあると、対話で名前の変更かを聞いてきて止まるため)
  1. 列の追加・NULL 可・一意制約だけを schema.ts に入れて `pnpm db:generate` → `drizzle/0004_*.sql`
  2. 続けて `sourceSha` と `importErrors` を消して `pnpm db:generate` → `drizzle/0005_*.sql`
  - 対話の質問が出たら作業を止め、その質問を報告に書く (SQL を手で書かない)
- 変更 テストの nodes の insert から `sourceSha` を消す: `src/test/pglite.test.ts`、`src/lib/devloop/{view,task-cache,owner-inbox,board,control,iteration-manifest}.test.ts`、`src/lib/mcp/{devloop-tools,handler,loop-tools}.test.ts` (typecheck で見つかったものを直す。iterations の `sourceSha` は残す)
- 変更 `src/test/pglite.test.ts`: テストを 2 つ足す: (a) `sourceRepo`・`detailPath` が null の Node を入れられる、(b) 同じ `sourceRepo` の Node は 2 つ目の insert が失敗する
- 変更 `src/lib/nodes/detail.ts`: `NodeDetail.node` に `repoReachable: boolean` を足す。Markdown を読むのは `sourceRepo` と `detailPath` があり `repoReachable` が true のときだけ (それ以外は markdown を null)
- 変更 `src/lib/nodes/asset.ts`: `isAllowedAsset` の `detailPath` を `string | null` にする
- 変更 `src/app/api/nodes/[id]/asset/route.ts`: `sourceRepo` が null か `repoReachable` が false なら 404
- 変更 `src/lib/devloop/control.ts`: `nextProject` の候補の取得に「`nodes.sourceRepo` が NULL でない」かつ「`nodes.repoReachable` が true」の条件を足す。`NextProject.sourceRepo` は `string` のまま (条件で絞ったうえで型を狭める)

## 触らない範囲
`src/lib/devloop/control.ts` の選び方の他の決まり (上限・一時停止・順番)、MCP のツールの説明文 (PBI-083)、`src/components/`、`iterations` テーブル、上に無いファイル

## 受け入れ条件
1. 検証コマンド 1 の出力が `2`
2. 検証コマンド 2 の出力が `2` 以上 (0005 に DROP がある)
3. 検証コマンド 3 の出力が `1` 以上 (0004 に repo_id がある)
4. 検証コマンド 4 (pglite.test) が pass し、足した 2 件を含む
5. 検証コマンド 5 (typecheck) の終了コードが 0
6. 検証コマンド 6 (test:unit) の終了コードが 0
7. 検証コマンド 7 (lint) の終了コードが 0

## 検証コマンド
リポジトリのルートから Git Bash で実行する。
1. `ls drizzle/0004_*.sql drizzle/0005_*.sql | wc -l`
2. `cat drizzle/0005_*.sql | /usr/bin/grep -ci "drop"`
3. `cat drizzle/0004_*.sql | /usr/bin/grep -c "repo_id"`
4. `pnpm vitest run src/test/pglite.test.ts`
5. `pnpm typecheck`
6. `pnpm test:unit`
7. `pnpm lint`
