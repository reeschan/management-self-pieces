# PBI-083: MCP と devloop の制御で、リポジトリの無い・届かない Node の扱いを確かめる

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review normal）
- 依存: PBI-082

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
MCP の `sourceRepo` は名前と形を保ち、リポジトリの無い Node では null を返す。`next_project` はリポジトリがあり届く Node だけを選ぶ (PBI-082 で選び方を直した)。これをテストで固め、ツールの説明文を直す。

## 対象
- 変更 `src/lib/devloop/control.test.ts`: `nextProject` のテストを足す: (a) `sourceRepo` が null の Node は選ばれない、(b) `repoReachable` が false の Node は選ばれない、(c) 同じ条件で届く Node なら選ばれる
- 変更 `src/lib/mcp/handler.test.ts`: `list_nodes` と `get_project` が、リポジトリの無い Node で `sourceRepo: null` を返すテストを足す
- 変更 `src/lib/mcp/tools.ts`: `list_nodes` の説明文に「sourceRepo はリポジトリの無い Node では null」を足す (他の文言と挙動は変えない)
- 変更 `src/lib/mcp/devloop-tools.ts`: `next_project` の説明文に「リポジトリがあり、届く Node だけから選ぶ」を足す

## 触らない範囲
ツールの入出力の形と名前、`src/lib/devloop/control.ts` (テストが落ちたときだけ、`nextProject` の候補の条件を最小限直してよい。その場合は報告に書く)、上に無いファイル

## 受け入れ条件
1. 検証コマンド 1 が pass し、足したテストを含む
2. 検証コマンド 2 の出力が `1` 以上
3. 検証コマンド 3 の出力が `1` 以上
4. 検証コマンド 4 (typecheck) の終了コードが 0
5. 検証コマンド 5 (lint) の終了コードが 0

## 検証コマンド
リポジトリのルートから Git Bash で実行する。
1. `pnpm vitest run src/lib/devloop/control.test.ts src/lib/mcp/handler.test.ts`
2. `/usr/bin/grep -c "null" src/lib/mcp/tools.ts`
3. `/usr/bin/grep -c "届く" src/lib/mcp/devloop-tools.ts`
4. `pnpm typecheck`
5. `pnpm lint`

## 補足
- 並列で PBI-085・086 が `src/lib/nodes/` と `src/lib/manifest/schema.ts` を作っている。そこは触らない
- テストの Node の用意は既存のテストの書き方 (同じファイルの insert) に合わせる
