# PBI-084: RepoSource を広げ、テスト用の偽物を作る

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review normal）
- 依存: PBI-080

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
候補の一覧・登録の初期値・つながりの更新に、リポジトリの id・説明・topics などと、id でリポジトリを引く手段が要る。GitHub の接点 (`RepoSource`) を広げ、以後のテストで使う偽物を用意する。

## 対象
- 変更 `src/lib/github/types.ts`: `RepoRef` と `RepoSource` を `docs/pbi/_node_common.md` の「GitHub」のとおりにする (`getRepoById` を足す)
- 変更 `src/lib/github/app.ts`:
  - GitHub の API が返すリポジトリのオブジェクトを `RepoRef` に直す純粋関数 `toRepoRef(raw)` を export する (`topics` が無ければ `[]`、`homepage` が空文字なら null、`description` が無ければ null)
  - `listRepos`・`getRepo` はそれを使って `RepoRef` を返す
  - `getRepoById(id)`: App のインストールごとに Installation のクライアントで `GET /repositories/{id}` を試し、最初に見つかったものを返す。どれでも 404 なら null。インストールの一覧は今の `listRepos` と同じ取り方
- 新規 `src/lib/github/app.test.ts`: `toRepoRef` のテスト (全項目が揃う場合、topics・homepage・description が無い場合)
- 新規 `src/test/fake-repo-source.ts`: `createFakeRepoSource(repos: (Partial<RepoRef> & { fullName: string; files?: Record<string, string>; throws?: boolean })[])` を export する。返り値は `RepoSource`。`listRepos` は throws でないものを返す。`getRepo`・`getRepoById` は名前 (大文字小文字を区別しない)・id で探して無ければ null、`throws` なら例外。`getFile` は `files[path]` を `{ content, sha: "fake" }` で返し、無ければ null。`getRawFile` は `files[path]` のバイト列。足りない項目は `id` が 1 からの連番、`defaultBranch: "main"`、`description: null`、`topics: []`、`homepage: null`、`htmlUrl: "https://github.com/" + fullName`、`archived: false` で埋める
- 新規 `src/test/fake-repo-source.test.ts`: 偽物の振る舞いのテスト (見つかる・見つからない・例外・ファイル)

## 触らない範囲
`src/lib/github/webhook.ts`、`src/lib/nodes/`、`src/db/`、上に無いファイル。GitHub の環境変数の読み方と Installation Token の取り方は変えない

## 受け入れ条件
1. 検証コマンド 1 が pass する
2. 検証コマンド 2 (typecheck) の終了コードが 0
3. 検証コマンド 3 (lint) の終了コードが 0
4. 検証コマンド 4 の出力が `1` 以上

## 検証コマンド
リポジトリのルートから Git Bash で実行する。
1. `pnpm vitest run src/lib/github/app.test.ts src/test/fake-repo-source.test.ts`
2. `pnpm typecheck`
3. `pnpm lint`
4. `/usr/bin/grep -c "getRepoById" src/lib/github/app.ts`

## 補足
- 並列で PBI-082 がスキーマとテストの insert を直している。typecheck がそちらの途中で落ちたら、その旨を報告に書く
- 実際の GitHub には接続しない (app.ts のテストは `toRepoRef` だけ)
- 既存の呼び出し元 (`src/lib/nodes/detail.ts`・`src/app/api/nodes/[id]/asset/route.ts`) は `getRepo(...).defaultBranch` だけを使うので、型を広げても動く
