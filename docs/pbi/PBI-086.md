# PBI-086: リポジトリとのつながりの更新を作る

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review deep）
- 依存: PBI-082, PBI-084

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
リポジトリの名前の変更や、App から外されたことを Node に反映する。Node は消さず、名前と「届くか」だけを直す。Webhook と Cron (PBI-088) がこれを呼ぶ。

## 対象
- 新規 `src/lib/nodes/repo-link.ts`: 契約 (`docs/pbi/_node_common.md` の「つながりの更新」) のとおり `createRepoLinkService` を作る。振る舞い:
  - 1 つの Node を確かめる手順: `repoId` があれば `getRepoById(repoId)`、無ければ `getRepo(sourceRepo)`。見つかれば `sourceRepo`・`repoId` を最新にし `repoReachable` を true に (変化があれば `updated` に数え、`updatedAt` を now に)。null なら `repoReachable` を false に (`unreachable` に数える)。例外なら何も変えず `failed` に数える
  - `refreshAll`: `sourceRepo` が NULL でない全 Node を上の手順で確かめる (`checked` は確かめた数)
  - `refreshRepos(repos)`: `repoId` が repos の id のどれかに一致するか、`repoId` が無く `sourceRepo` が repos の名前のどれか (大文字小文字を区別しない) に一致する Node だけを確かめる
  - `markUnreachable(repos)`: 同じ一致の決まりで Node に `repoReachable = false` を付け、付けた数を返す (GitHub は呼ばない)
  - 名前を更新すると一意制約にぶつかる (別の Node が既にその名前を持つ) 場合は、更新せず `failed` に数える
  - どの操作も Node を消さない
- 新規 `src/lib/nodes/repo-link.test.ts`: **実装より先に書く**。PGlite と `createFakeRepoSource` で: 名前の変更が反映される (id で引ける)、repoId が無い既存の Node に id が埋まる、見つからないと届かない印、例外だと変えない、届かない Node が見つかれば戻る、refreshRepos が他の Node を確かめない、markUnreachable の一致 (id と名前)、リポジトリの無い Node は対象外、どの場合も Node の数が減らない
