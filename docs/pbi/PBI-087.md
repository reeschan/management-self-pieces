# PBI-087: Node の書き出しと読み込み (JSON) を作る

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review deep）
- 依存: PBI-085

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
DB が正になったので、消えたときの備えとして、Node・リポジトリとのつながり・関係を JSON で書き出し、読み込めるようにする。seed (PBI-089) と設定画面 (PBI-092) がこれを使う。

## 対象
- 新規 `src/lib/nodes/transfer.ts`: 契約 (`docs/pbi/_node_common.md` の「書き出しと読み込み」) のとおり。`ExportFile` の Zod スキーマは `src/lib/nodes/input.ts` の部品を使う。振る舞い:
  - `exportNodes`: 全 Node (id の昇順) と全関係 (from・to・type の昇順) を返す。各 Node の `repo` は `sourceRepo` があれば `{ id: repoId, fullName: sourceRepo }`、無ければ null。`repoReachable`・`createdAt`・`updatedAt` は含めない。`exportedAt` は now の ISO 文字列
  - 検証 (`previewImport` と `importNodes` で共通): 形が `ExportFile` に合う (version は 1)、各 Node が `NodeCreateInput` の決まり (meta の型・リポジトリの無い Node の detailPath と diagrams) に合う、ファイルの中で id とリポジトリ (id か名前の大文字小文字を区別しない一致) が重ならない、関係の先と元がファイルか DB にある、リポジトリが DB の別の id の Node に結び付いていない。エラーはすべて集めて、`パス: 理由` の日本語の文字列の配列にする
  - `previewImport`: 検証に通れば、DB に無い id の数を `added`、ある id の数を `updated` として返す
  - `importNodes`: 検証に落ちたら `NodeServiceError("invalid")` を投げて何も書かない。通れば Node を id で upsert し (新しい Node は `repoReachable` true・`createdAt` now、既存の Node は `repoReachable`・`createdAt` を変えない、どちらも `updatedAt` は now)、関係は無ければ足す (`onConflictDoNothing`)。ファイルに無い Node と関係は消さない
- 新規 `src/lib/nodes/transfer.test.ts`: **実装より先に書く**。PGlite で: 書き出しの形と順番、書き出し → 空の DB に読み込み → もう一度書き出すと `exportedAt` 以外が同じ (往復)、プレビューの件数、壊れたファイル (形の違い・関係の先が無い・リポジトリの重なり・DB の別の Node のリポジトリ) で何も変わらずエラーが返る、ファイルに無い Node と関係が消えない、既存の Node の `repoReachable` が保たれる
