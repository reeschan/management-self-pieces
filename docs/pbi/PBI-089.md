# PBI-089: fixtures を書き出し JSON の形にし、seed を読み込みで行う

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review normal）
- 依存: PBI-087

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
開発用の fixtures を書き出し JSON と同じ形の 1 ファイルにし、seed は読み込みの処理 (`importNodes`) を使う。読み込みの処理を普段から試すことになる。

## 対象
- 新規 `fixtures/nodes.json`: 今の `fixtures/*.yaml` (6 件) の中身を `ExportFile` の形に移す (`version: 1`、`exportedAt` は任意の ISO 文字列)。各 Node の `repo` は `{ id: null, fullName: "reeschan/<id>" }`、`detailPath` は yaml の `detail` (無ければ `README.md`)、他の項目は yaml のとおり。yaml の `relations` は `relations` の配列に移す
- 削除: `fixtures/*.yaml` (6 件)
- 変更 `scripts/seed.mts`: `fixtures/nodes.json` を読み、`previewImport` の結果 (件数かエラー) を出してから `importNodes(getDb(), raw, () => new Date())` を呼ぶ。検証エラーなら、エラーを出して終了コード 1。今の `EnvError` の扱いは残す
- 新規 `scripts/fixtures.test.ts`: PGlite に `fixtures/nodes.json` を `previewImport` すると `ok: true` で `added` が 6、`importNodes` のあと `exportNodes` の Node が 6 件

## 触らない範囲
`src/lib/nodes/`、`package.json`、上に無いファイル

## 受け入れ条件
1. 検証コマンド 1 が pass する
2. 検証コマンド 2 の出力が `0`
3. 検証コマンド 3 (typecheck) の終了コードが 0
4. 検証コマンド 4 (lint) の終了コードが 0

## 検証コマンド
リポジトリのルートから Git Bash で実行する。
1. `pnpm vitest run scripts/fixtures.test.ts`
2. `ls fixtures/*.yaml 2>/dev/null | wc -l`
3. `pnpm typecheck`
4. `pnpm lint`

## 補足
- 本番や開発の DB に seed を流さない (検証は PGlite のテストだけ)
- 並列で PBI-091・092・093 が画面を作っている。そこは触らない
