# PBI-090: Node 画面 (一覧と候補) と Server Actions を作る

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review normal）
- 依存: PBI-085

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
持ち主が登録済みの Node と、まだ Node になっていないリポジトリ (Node の候補) を 1 画面で見られるようにし、登録・編集・削除の Server Actions を用意する (フォームは PBI-091)。

## 対象
- 新規 `src/lib/nodes/server.ts`: サーバー側でサービスを作る関数 `getNodeService()` (`createNodeService({ db: getDb(), source: createRepoSource, now: () => new Date() })`)。既存のコードで `server-only` を使っていれば同じ書き方で付ける
- 新規 `src/app/(app)/nodes/actions.ts` (`"use server"`): `createNode(input: unknown): Promise<{ id: string }>`、`updateNode(id: string, input: unknown): Promise<void>`、`deleteNode(id: string): Promise<void>`。書き方は `src/app/(app)/devloop/actions.ts` に合わせる: 最初に `getAllowedSession()`、id は `NodeId` で検証、`NodeServiceError` はその message で `Error` を投げ直し、それ以外は console.error に出して「処理に失敗しました」。成功したら `revalidatePath("/")` と `revalidatePath("/nodes")`
- 新規 `src/app/(app)/nodes/page.tsx`: サーバーコンポーネント。上段に登録済みの Node の表 (id・title・kind・status・リポジトリ (無ければ「なし」)・届かなければ「届かない」の印、各行から `/nodes/<id>/edit` へのリンク)。下段に候補の表 (`listCandidates()`。リポジトリの名前・description・「登録する」リンク `/nodes/new?repo=<fullName を encodeURIComponent したもの>`)。候補の取得が失敗したら (GitHub の環境変数が無い・例外)、表の代わりに「GitHub から候補を読めませんでした」と出し、登録済みの表は出す。上部に「リポジトリ無しで作る」リンク (`/nodes/new`)。見た目は `src/app/(app)/settings/page.tsx` の節の書き方 (section・h2・Tailwind のクラス) に合わせる。データを読む前に `connection()` を呼ぶ (settings/page.tsx と同じ)

## 触らない範囲
`src/lib/nodes/service.ts`・`input.ts` (使うだけ)、ナビゲーション (PBI-093)、フォーム (PBI-091)、上に無いファイル

## 受け入れ条件
1. 検証コマンド 1 の出力が `3` 以上
2. 検証コマンド 2 (typecheck) の終了コードが 0
3. 検証コマンド 3 (lint) の終了コードが 0
4. 検証コマンド 4 の出力の 1 行目が `exit=0` で、`/nodes` を含む行がある

## 検証コマンド
リポジトリのルートから Git Bash で実行する。
1. `/usr/bin/grep -c "getAllowedSession" 'src/app/(app)/nodes/actions.ts'`
2. `pnpm typecheck`
3. `pnpm lint`
4. `pnpm build > docs/pbi/verify/build.$$.log 2>&1; echo "exit=$?"; /usr/bin/grep -E "/nodes" docs/pbi/verify/build.$$.log | head -n 5`
