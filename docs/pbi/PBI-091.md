# PBI-091: Node の登録・編集フォームと、その画面を作る

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review normal）
- 依存: PBI-090

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
候補から、またはリポジトリ無しで Node を登録し、登録済みの Node を直し、消せる (または消せない理由を見る) 画面を作る。

## 対象
- 新規 `src/components/nodes/node-form.tsx` (クライアントコンポーネント): 登録と編集で共用するフォーム。props は初期値 (`NodeCreateInput` の形)、モード (`create` | `edit`)、関係の先の候補 (`{ id, title }[]`)、編集なら消せない理由 (`("asana" | "devloop")[]`)
  - 欄: id (登録のときだけ編集可)、リポジトリ (表示だけ。無ければ「なし」)、kind (選択)、title、summary、status (選択)、tags (カンマ区切り)、links (名前と URL の行の追加・削除)、詳細のパス (リポジトリが無ければ出さない)、図 (パスとタイトルの行。リポジトリが無ければ出さない)、関係 (種類と先の Node を選ぶ行。自分は選べない)、meta
  - meta: kind を選ぶと、`src/lib/manifest/kinds.ts` の `kinds[kind].meta.shape` のキーごとに入力欄を出す (ラベルはキーと description)。それ以外のキーは key-value の行で足す。空の値は送らない
  - 送信: 登録は `createNode`、編集は `updateNode` を呼ぶ。成功したら `/nodes` へ移る。失敗したら Error の message をフォームの上に出す
  - 削除のボタン (編集のときだけ): 消せない理由があれば押せない状態にし、理由 (Asana との対応がある / devloop の記録がある、archived にするよう案内) を出す。押せるときは確認 (`confirm`、「この Node に向いた関係も消えます」) のあと `deleteNode` を呼び、`/nodes` へ移る
- 新規 `src/app/(app)/nodes/new/page.tsx`: `searchParams` の `repo` があれば `getNodeService().draftFromRepo(repo)` を初期値にする (失敗したら、空の初期値で「リポジトリの情報を読めませんでした」と出す)。無ければ空の初期値 (repo は null、detailPath は null)。関係の先の候補は全 Node
- 新規 `src/app/(app)/nodes/[id]/edit/page.tsx`: Node と、その Node から出る関係を読み、初期値にする。無ければ `notFound()`。`deletionBlockers` を渡す。関係の先の候補は自分以外の全 Node

## 触らない範囲
`src/app/(app)/nodes/actions.ts`・`page.tsx` と `src/lib/nodes/` (使うだけ)、上に無いファイル

## 受け入れ条件
1. 検証コマンド 1 の出力が `ok`
2. 検証コマンド 2 (typecheck) の終了コードが 0
3. 検証コマンド 3 (lint) の終了コードが 0
4. 検証コマンド 4 の出力の 1 行目が `exit=0` で、`/nodes/new` を含む行がある

## 検証コマンド
リポジトリのルートから Git Bash で実行する。
1. `test -f src/components/nodes/node-form.tsx && test -f 'src/app/(app)/nodes/new/page.tsx' && test -f 'src/app/(app)/nodes/[id]/edit/page.tsx' && echo ok`
2. `pnpm typecheck`
3. `pnpm lint`
4. `pnpm build > docs/pbi/verify/build.$$.log 2>&1; echo "exit=$?"; /usr/bin/grep -E "/nodes" docs/pbi/verify/build.$$.log | head -n 5`
