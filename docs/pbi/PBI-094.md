# PBI-094: 文書を直し、このリポジトリの node.yaml を消す

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review normal）
- 依存: PBI-080〜093

共通の決まりとモジュールの契約: `docs/pbi/_node_common.md` を最初に読み、従う。

## 目的
Node の正がアプリに移ったことを文書に反映し、使われなくなったこのリポジトリの `node.yaml` を消す。

## 対象
- 変更 `docs/DESIGN.md`:
  - 方針の「データの正」: Node の中身はアプリの DB が正 ([ADR 0003](adr/0003-node-source-of-truth-in-app.md))、チケットと看板は Asana が正、備えは設定画面の JSON の書き出しと読み込み、と書き直す (MCP と devloop の運用データの文は残す)
  - 方針の「仕様の正」(node.yaml の Zod スキーマと `/schema/node.json`) を、「Node の入力の検証は `src/lib/nodes/input.ts` (kind の登録表は `src/lib/manifest/kinds.ts`)」に書き換える
  - 方針の「GitHub 連携」: 取り込み (Installation Token) を「候補の一覧・詳細と図の読み出し・つながりの更新」に、Webhook (push) を Webhook (repository・installation_repositories・installation) に直す
  - ディレクトリ: `import/` を消し、`(app)/nodes/` (Node 画面・登録・編集)・`lib/nodes/` (Node のサービス・つながりの更新・書き出しと読み込み)・`components/nodes/` を足す。`schema/node.json/route.ts` を消す
  - テーブル: `nodes` の列を今の形に (`repo_id`・`repo_reachable`・`created_at`、`source_sha` なし)、`import_errors` の行を消す
  - 取り込みの流れを説明している節があれば、「登録 (候補から) → 編集 → つながりの更新」の流れに書き換える
- 変更 `docs/SETUP.md`: GitHub App の Webhook のイベントを `push` から `repository`・`installation_repositories`・`installation` に直す (購読に要る権限は、オーケストレーターが確かめた値を補足に書く)。node.yaml の書き方・置き方の節があれば、「Node 画面 (`/nodes`) で候補から登録する」に書き換える。`pnpm db:seed` の説明を `fixtures/nodes.json` に直す
- 変更 `README.md`: node.yaml と seed の説明を今の形に直す
- 削除: リポジトリのルートの `node.yaml`

## 触らない範囲
`docs/specs/`・`docs/adr/`・`CONTEXT.md`、ソースコード、上に無いファイル

## 受け入れ条件
1. 検証コマンド 1 の出力が `ok`
2. 検証コマンド 2 の出力が空 (一致 0 件で終了コード 1)
3. 検証コマンド 3 の出力が `1` 以上
4. 検証コマンド 4 の出力が `1` 以上

## 検証コマンド
リポジトリのルートから Git Bash で実行する。
1. `test ! -e node.yaml && echo ok`
2. `/usr/bin/grep -n "node.yaml\|schema/node.json\|import_errors\|source_sha" docs/DESIGN.md docs/SETUP.md README.md | /usr/bin/grep -v "| iterations |"` (iterations の source_sha は残す列なので除く。オーケストレーターが 2026-10-14 に直した)
3. `/usr/bin/grep -c "0003-node-source-of-truth-in-app" docs/DESIGN.md`
4. `/usr/bin/grep -c "installation_repositories" docs/SETUP.md`

## 補足
- GitHub App の Webhook の権限 (オーケストレーターが GitHub の文書 docs.github.com/en/webhooks/webhook-events-and-payloads で確かめた、2026-10-14): `repository` イベントを購読するには、リポジトリの権限の **Metadata を Read** にする (それで足りる)。App の設定の「Subscribe to events」で `Repository` にチェックを入れる。`installation` と `installation_repositories` は GitHub App に既定で届き、購読の設定は無い (チェック欄も無い)。SETUP.md にはこの 3 点をこのとおりに書き、`push` の購読は外してよいと書く
- 文体は既存に合わせる (常体、簡潔)
- 検証コマンド 2 に当たる記述は、廃止したことを説明する文でも残さない (経緯は ADR 0003 にある)
- `iterations` の `source_sha` は devloop のもので別物。DESIGN.md の iterations の行にある `source_sha` だけが検証コマンド 2 に当たったら、残して報告に書く
