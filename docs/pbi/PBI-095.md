# PBI-095: Node の操作のエラーを戻り値で返す (本番でも理由が画面に出るように)

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash（sonnet 相当、review normal）
- 依存: PBI-090, PBI-091, PBI-092

## 目的
Next.js は本番のビルドで、サーバーアクション (Server Functions) が throw した Error の message を消し、クライアントには汎用のエラーだけが届く。そのため Node の登録・編集・削除と、書き出し・読み込みで失敗したとき (例: 「ID「x」は既に使われています」) に、本番では理由が画面に出ない。Next.js の文書 (`node_modules/next/dist/docs/01-app/01-getting-started/10-error-handling.md` の「Handling expected errors」) のとおり、想定内のエラーは throw せず戻り値で返す形に直す。対象は Node の操作だけ (devloop・設定の既存の操作は今回は直さない)。

## 対象
- 新規 `src/lib/action-result.ts`:
  - `export type ActionResult<T> = { ok: true; value: T } | { ok: false; message: string };`
  - `export function actionError(e: unknown, log: string): { ok: false; message: string }`: `e` が `NodeServiceError` (`@/lib/nodes/service`) ならその message を返す。それ以外は `console.error(log, e)` を出して message「処理に失敗しました」を返す
  - `export const UNAUTHORIZED: { ok: false; message: string }` (message「ログインし直してください」)
- 新規 `src/lib/action-result.test.ts`: `actionError` のテスト (NodeServiceError の message がそのまま返る / それ以外は「処理に失敗しました」で console.error が呼ばれる (vi.spyOn))
- 変更 `src/app/(app)/nodes/actions.ts`: `createNode` は `Promise<ActionResult<{ id: string }>>`、`updateNode`・`deleteNode` は `Promise<ActionResult<null>>` を返す。セッションが無ければ `UNAUTHORIZED`、id の検証に落ちたら `{ ok: false, message: "入力が正しくありません" }`、サービスの例外は `actionError(e, "[nodes:actions] 処理に失敗しました")`。`throw` を残さない。成功のときだけ `revalidatePath` する (今と同じ 2 つ)
- 変更 `src/app/(app)/settings/node-transfer-actions.ts`: `exportNodesAction` は `Promise<ActionResult<string>>`、`importNodesAction` は `Promise<ActionResult<{ added: number; updated: number }>>`。`previewImportAction` は今の `ImportPreview` を返したまま、セッションが無いときと想定外の例外のときも throw せず `{ ok: false, errors: [<message>] }` を返す。大きすぎる・JSON として読めないときの文言は今のまま。`throw` を残さない
- 変更 `src/components/nodes/node-form.tsx`: 上の戻り値を見て、`ok: false` なら `setError(result.message)` し、遷移しない。`ok: true` のときだけ今と同じく `router.push("/nodes")`。通信の失敗などで呼び出し自体が例外になったときに備えて try/catch は残し、そのときは「通信に失敗しました」を出す (`caught.message` は出さない)
- 変更 `src/components/settings/node-transfer-section.tsx`: 同じく戻り値を見てエラーを出す。try/catch の例外のときは「通信に失敗しました」

## 補足
- サーバーアクションの書き方 (先頭で `getAllowedSession()`、`"use server"`) は今の `src/app/(app)/nodes/actions.ts` のまま
- `"use server"` のファイルから export できるのは async 関数だけ。型 (`ActionResult`) と `actionError`・`UNAUTHORIZED` は `src/lib/action-result.ts` に置き、actions のファイルからは export しない
- `next dev` では throw の message が届くので、開発中は今の形でも理由が出る。本番のビルドで消えるのが問題
- 並列で動く PBI は無い
