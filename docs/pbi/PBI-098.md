# PBI-098: 設定画面の操作 (トークン・IP 許可リスト) のエラーを戻り値で返す

- 担当モデル: agent sonnet high（sonnet 相当、sensitive のため review deep）
- 依存: なし

## 目的
Next.js は本番のビルドで、サーバーアクションが throw した Error の message を消す。設定画面のエージェント用トークンの発行・失効と、IP 許可リストの追加・削除・今の IP の許可は、失敗の理由 (「CIDR の形が正しくない」など) を throw で伝えているため、本番では理由が画面に出ない。PBI-095 で Node の操作に入れた `ActionResult` の形にそろえる。

## 対象
- 変更 `src/app/(app)/settings/actions.ts`: 5 つの関数の戻り値を次に変える。`throw` と zod の `.parse(` を残さない (`safeParse` にする)
  - `issueAgentToken`: `Promise<ActionResult<{ id: string; raw: string }>>`
  - `revokeAgentToken`・`removeIpAllowlist`: `Promise<ActionResult<boolean>>` (今の true / false の意味のまま)
  - `addIpAllowlist`・`allowCurrentIp`: `Promise<ActionResult<string>>`
  - セッションが無ければ `UNAUTHORIZED`。入力の検証に落ちたら次の文言を返す:
    - トークンの名前が前後の空白を除いて 1〜60 文字でない: 「名前は 1〜60 文字で指定してください」
    - IP 許可リストのラベルが前後の空白を除いて 1〜60 文字でない (`addIpAllowlist`・`allowCurrentIp` とも): 「ラベルは 1〜60 文字で指定してください」
    - CIDR が `normalizeCidr` で null: 「CIDR の形が正しくありません」
    - 今の IP を取れない (今の `allowCurrentIp` の条件): 「今の IP を取得できません (ローカルで動いているときは IP 許可リストは使いません)」
    - それ以外の検証の失敗 (scopes が空・重複、期限の日数、id の形など): 「入力が正しくありません」
  - `issueToken`・`revokeToken`・`addAllowlistEntry`・`removeAllowlistEntry` の例外は try/catch で受け、`actionError(e, "[settings:actions] 処理に失敗しました")` を返す
  - `revalidatePath("/settings")` は成功したときだけ
  - トークンの値 (`raw`) は今と同じく戻り値でだけ返し、ログ・エラーの文言に入れない
- 変更 `src/components/settings/token-section.tsx`・`src/components/settings/ip-section.tsx`: 戻り値を見て、`ok: false` なら `setError(result.message)` し、成功のときの処理 (値の表示・入力欄を空にする等) をしない。成功のときは `result.value` を今の戻り値の代わりに使う。try/catch の例外のときは「通信に失敗しました」。クリップボードへのコピーの try/catch (token-section.tsx の 62 行目あたり) は今のまま
