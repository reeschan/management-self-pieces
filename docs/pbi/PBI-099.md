# PBI-099: チケットの操作 (Asana のつなぎ・タスクの作成・取り直し) のエラーを戻り値で返す

- 担当モデル: opencode opencode-go/deepseek-v4.1-flash max（sonnet 相当、review normal）
- 依存: なし

## 目的
Next.js は本番のビルドで、サーバーアクションが throw した Error の message を消す。Node のパネルの「チケット」タブから使う 3 つの操作は、入力の誤りも Asana の失敗も throw で伝えている。PBI-095 で Node の操作に入れた `ActionResult` の形にそろえ、失敗したことと理由が本番でも画面に出るようにする。

## 対象
- 変更 `src/app/(app)/actions.ts`: 3 つの関数の戻り値を次に変える。`throw` と zod の `.parse(` を残さない (`safeParse` にする)
  - `linkAsanaProject`: `Promise<ActionResult<ExternalRef>>`
  - `createTask`: `Promise<ActionResult<TrackerTask>>`
  - `refreshNodeTasks`: `Promise<ActionResult<number>>`
  - セッションが無ければ `UNAUTHORIZED`。Node の id の検証に落ちたら「入力が正しくありません」。タスクの入力の検証に落ちたら「タスク名は 1〜200 文字、期日は YYYY-MM-DD で指定してください」
  - `linkNodeToAsana`・`createTaskForNode`・`refreshTasks` の例外は try/catch で受け、`actionError(e, "[tracker:actions] 処理に失敗しました")` を返す
  - `revalidatePath("/")` は成功したときだけ
- 変更 `src/components/panel/tickets-tab.tsx`: `run` を、`action: () => Promise<ActionResult<unknown>>` を受けて、`ok: false` なら `setError(result.message)` して onSuccess・onChanged を呼ばない形に変える (入力欄も空にしない)。try/catch の例外のときは「通信に失敗しました」

## 触らない範囲
`src/lib/tracker/` (使うだけ)。`src/lib/action-result.ts`。`taskInputSchema` の条件 (200 文字・日付の形) は変えない。`src/app/(app)/devloop/`・`src/app/(app)/settings/`・`src/app/(app)/nodes/`。上に無いファイル

3. 検証コマンド 3 の出力が 3 以上
4. 検証コマンド 4 (typecheck) の終了コードが 0
5. 検証コマンド 5 (lint) の終了コードが 0
6. 検証コマンド 6 (test:unit) の終了コードが 0
